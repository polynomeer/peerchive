# Peerchive 신규 앱

2019년 원본 ProofU(`frontend/`, `backend/`)와 별개로 만드는 신규 앱입니다. 원본은 기록 보존 대상이며 이 워크스페이스에 포함되지 않습니다. 결정 배경은 [ADR](../docs/adr/README.md)과 [시스템 설계](../docs/planning/SYSTEM_DESIGN.md)를 보세요.

## 구성

| 경로 | 내용 |
|---|---|
| `apps/web` | Nuxt 4(Vue 3, TypeScript strict). 화면(`app/`), `/api/v1` 라우트(`server/api`), 서비스 모듈(`server/modules`), 공유 DTO 타입(`shared/types`) |
| `apps/worker` | 작업 worker(pg-boss, [ADR 0004](../docs/adr/0004-pg-boss-jobs.md)). outbox 전달, 파일 검사 작업, 공개 게시·철회 이벤트(파생 데이터 정리 handler 등록 구조·`publication.derived_cleanup` 감사, [ADR 0012](../docs/adr/0012-publish-withdraw-public-read.md)), 과목 허브 파생 데이터(검색 색인·유용성 신호 정리·선배 노트 색인, [ADR 0013](../docs/adr/0013-course-hub-search-fork.md)), 케이스 스터디 이용 불가 표시(철회·대체된 release, [ADR 0014](../docs/adr/0014-case-study-portfolio.md)), 운영 조치의 검색 문서 맞추기(`moderation.action`, [ADR 0015](../docs/adr/0015-reports-moderation-appeals.md)), 운영 주기 작업(만료 행·격리 파일 정리, 탈퇴 계정 정리·삭제 장부)·상태 기록·재적용 명령([ADR 0016](../docs/adr/0016-deletion-ledger-maintenance-analytics.md)), 이름 표시 방식 변경 적용(`name-mode-changes` 매분·`apply-name-modes` 명령, [ADR 0020](../docs/adr/0020-name-modes.md)) |

| `apps/e2e` | 브라우저 E2E(Playwright, Chromium). 빌드한 web 서버·worker를 전용 DB `peerchive_e2e`로 띄워 수용 시나리오를 desktop·mobile(360px)에서 확인([실행 안내](e2e/README.md)) |
| `packages/domain` | 런타임 의존성 없는 도메인 규칙: 과제 공간 권한 정책, 빌드 로그 작성·수정·해결 연결 규칙, 공개 상태 전이(게시 중 새 버전 `republish` 포함)·공개 후보 권한·결정적 JSON(manifest 해시)·공개 전 점검 규칙·공개 조회 판정(`canServePublicRelease`/`canServePublicArtifact`), 역할 선언·팀원 확인·기여 장부 기간 규칙, 산출물 업로드·열람 정책과 검사 상태 전이, 마일스톤·할 일·사후 작성 규칙, 주간 체크인 주(서울 ISO 주)·알림 일정·익명 집계(n≥5), 학교·과목 이름 정규화 키·학기 종료 시각·개념 태그 slug·병합 전제 조건·단조 엠바고·적용 엠바고 계산, 과목 허브 작성 자격(`canWriteToCourseHub`)·선배 노트 답 검증·막힘 카드 추출·플랜 포크 허용 목록·검색 문서, 케이스 스터디 템플릿 초안(`generateCaseStudyDraft`)·인용 검증·출처 없는 문장 판정·역량 프리셋·역량 × 근거 개수(`computeCompetencyMatrix`), 신고·운영 조치 규칙(대상별 조치·보류 사유·신고/이의 상태 전이·가린 항목 제외 `redactHiddenItems`), 학교 메일 인증 규칙(도메인 정규화·하위 도메인 일치·공용 접미사/웹메일 거부·주소 정규화·코드 시도 판정·재학/졸업생 전환·학과 정규화, C-01), 커뮤니티 공간 정책(`canReadSpace`·`canPreviewSpace`·`canJoinSpace`·`canWriteBoard`·`canModerate`·`canManageSpace`·방장 승계 `chooseOwnerSuccessor`·예약어 이름·정원·기본 게시판·개설 요청 기준, C-02), 이름 표시 방식(전환 규칙·7일 예약·`effectiveNameMode`·작성 시점 고정 `nameModeAtWrite`·작성자 표시 `resolveAuthorDisplay`·실명 입력·알림 payload 허용 목록, C-03), 글·댓글(스레드 익명 번호 `assignThreadAlias`·표시 `threadAuthorView`·댓글/공감 권한·소규모 방 시각 버킷·자리 표시·입력 검사, C-04) |
| `packages/db` | Drizzle ORM 스키마, SQL migration(`migrations/`), `createDb(url)`, outbox 주제·payload(`src/outbox.ts`), 운영자 부여 CLI(`scripts/grant-operator.ts`) |
| `packages/bot-protocol` | 웹 ↔ 봇 내부 API 약속: HMAC-SHA256 요청 서명·검증(시각 차이 5분, nonce)과 요청/응답 타입 |
| `packages/files` | 오브젝트 저장소 추상화(파일시스템 driver), 파일 형식 판별, 악성코드 검사 어댑터(clamd), 검사 작업, 이미지 메타데이터 제거(EXIF/GPS/XMP/주석, 무손실)·PDF 문서 속성 점검과 backfill([ADR 0007](../docs/adr/0007-file-storage-and-scanning.md)) |
| `ops/docker-compose.yml` | 로컬 개발용 PostgreSQL 16, 선택 profile `clamav`(clamd)·`mailpit`(SMTP 시험 서버)·`minio`(S3 호환 저장소). 선택 서비스는 profile을 지정할 때만 뜸 |
| `ops/backup.sh`·`ops/restore.sh`·`ops/restore-drill.sh` | 백업(pg_dump custom + 파일 tar + 장부 + 행 수 + 체크섬, 보존 기간)·복구(덮어쓰기는 `--force`)·복구 연습(임시 DB, 재적용까지, 시간 출력). 절차는 [운영 runbook](../docs/ops/RUNBOOK.md) |

| 항목 | 목표 초안 | 담당 |
|---|---|---|
| 신고 접수 확인(대기열 확인·배정) | 업무일 24시간 이내 | 1차 담당: `<운영자 이름·연락 채널>` |
| 개인정보(`personal_info`)·저작권(`copyright`) 신고 처리 | 접수 후 24시간 이내(보류가 걸려 새 게시는 이미 막힘) | 1차: `<운영자>`, 대리: `<대리 운영자>` |
| 그 밖의 신고 처리 | 업무일 3일 이내 | `<운영자>` |
| 이의제기 결정 | 업무일 3일 이내, 가능하면 조치한 사람이 아닌 운영자 | `<운영자>` |
| 공개 읽기 전체 차단이 필요한 사고(권한 누출·파일 공개 오류) | 발견 즉시 운영 스위치 | 당번: `<on-call 이름·연락 채널>` |

- 운영자 부여·회수는 CLI(`pnpm --filter @peerchive/db grant-operator <email> [--revoke]`)로만 합니다. 공식 커뮤니티 페이지는 운영자만 `/operator/community`에서 엽니다(절차 [runbook §4.2](../docs/ops/RUNBOOK.md), C-02). 학교 메일 도메인은 운영자 API 또는 CLI(`pnpm --filter @peerchive/db school-email-domain add <schoolId> <domain>`)로 등록합니다(C-01, 파일럿 전에 학교마다). 운영자는 `/operator`에서 대기열(처리 전은 오래된 것부터)·상세·처리·이의 결정을 하고, 모든 처리는 감사 기록(`/api/v1/operator/audit?target=`)에 남습니다. 운영자도 비공개 과제 공간은 볼 수 없습니다.
- 조치는 공개 차단뿐입니다(제한·항목 가리기·숨김, 되돌릴 수 있음). 내용 삭제는 이 화면에 없으며 T-16의 삭제 절차·ledger로 따로 합니다.
- 배포 점검표·게이트 점검·사고 대응·복구 순서·백업 일정·데이터 보존은 [운영 runbook](../docs/ops/RUNBOOK.md)에 있습니다(T-16).
- **운영 스위치**: `PEERCHIVE_PUBLIC_READS_DISABLED=1`로 web을 재시작하면 `/api/v1/public/**` 전체가 DB를 건드리지 않고 503, 공개 페이지는 "잠시 볼 수 없음"입니다([ADR 0012](../docs/adr/0012-publish-withdraw-public-read.md)). 개별 사례는 스위치 대신 restrict로 막습니다(재시작 없이 즉시). 신고 접수(`POST /api/v1/reports`)는 스위치와 무관하게 계속 받습니다.

## 실행

```sh
pnpm install
cp .env.example .env                          # 로컬 전용 값. 실제 비밀값을 넣지 마세요.
docker compose -f ops/docker-compose.yml up -d
pnpm db:migrate
pnpm dev                                      # http://localhost:3000
pnpm worker                                   # 다른 터미널에서: 파일 검사 worker(개발 모드)
pnpm bot                                      # 선택: 디스코드 봇(토큰 필요, apps/bot/README.md)
pnpm test
```

- 로그인: `/login`에 이메일을 넣으면 `pnpm dev` 콘솔에 `[dev-console mail]` 블록으로 로그인 링크가 출력됩니다(개발 전용, 실제 메일 발송 없음). 실제 SMTP 경로를 보려면 아래 "SMTP·S3 로컬 시험"을 보세요.
- 5432 포트가 이미 쓰이고 있으면 `.env`의 `POSTGRES_PORT`와 `DATABASE_URL` 포트를 함께 바꾸고 `docker compose --env-file .env -f ops/docker-compose.yml up -d`로 띄우세요(compose는 기본적으로 `ops/.env`를 읽습니다).
- `pnpm test`는 `DATABASE_URL`이 없으면 DB 통합 테스트(`packages/db`, `apps/web/test/*.integration.test.ts`, `apps/worker/test/*.integration.test.ts`)를 건너뜁니다. 통합 테스트는 트랜잭션 rollback으로 데이터를 남기지 않습니다. 실행하려면 `DATABASE_URL=postgres://peerchive:peerchive@localhost:5432/peerchive pnpm test`.
- 공개 검색 결과는 worker가 게시 이벤트로 색인한 뒤에 나옵니다(`pnpm worker`). 과목 허브·사례 페이지·공개 프로필은 worker 없이도 바로 보이고, 철회는 worker와 무관하게 즉시 모든 공개 경로(공개 프로필의 케이스 스터디 포함)에서 사라집니다.
- 파일을 올리면 worker가 검사해야 "사용 가능"이 됩니다. 검사를 통과한 이미지는 EXIF/GPS/XMP/주석을 지운 내용이 저장되고("메타데이터 제거됨"), PDF는 그대로 두되 문서 속성에 작성자 정보가 있으면 표시·공개 전 경고합니다. 이 기능 전에 올린 이미지가 DB에 있으면 공개 전에 한 번 `NODE_ENV=development pnpm --filter worker backfill-strip`을 실행하세요. `pnpm worker`는 `NODE_ENV=development`로 실행하며 기본 검사기는 개발용 `signature-only`(형식 판별만)입니다. 실제 악성코드 검사를 해 보려면 `docker compose -f ops/docker-compose.yml --profile clamav up -d`(처음엔 서명 DB를 받느라 몇 분 걸림) 뒤 `.env`에 `PEERCHIVE_MALWARE_SCANNER=clamav`.
- 올린 파일은 저장소 루트의 `.data/objects/`(gitignore 대상)에 무작위 키로 저장됩니다. 웹 서버는 이 디렉터리를 정적으로 제공하지 않습니다.
- 끝나면 `docker compose -f ops/docker-compose.yml down`(데이터 볼륨 `peerchive-pg-data`는 유지, 지우려면 `down -v`). profile로 띄운 서비스까지 내리려면 같은 `--profile`을 붙이세요.

### SMTP·S3 로컬 시험(Mailpit·MinIO)

실제 공급자 없이 SMTP transport와 S3 driver를 확인합니다([ADR 0017](../docs/adr/0017-smtp-mail-and-s3-storage.md)). 두 서비스 모두 127.0.0.1에만 열리고 기본 `up`에는 뜨지 않습니다.

```sh
docker compose --env-file .env -f ops/docker-compose.yml --profile mailpit --profile minio up -d --wait mailpit minio
# 받은 메일: http://127.0.0.1:8025  /  MinIO 관리 화면: http://127.0.0.1:9001 (.env.example의 로컬 계정)
```

- 앱에서 쓰기: `.env`에 `PEERCHIVE_MAIL_TRANSPORT=smtp`, `PEERCHIVE_SMTP_URL=smtp://127.0.0.1:1025`, `PEERCHIVE_SMTP_ALLOW_INSECURE=1`, `PEERCHIVE_MAIL_FROM=…`과 `PEERCHIVE_STORAGE_DRIVER=s3`, `PEERCHIVE_S3_*`(MinIO 값, `PEERCHIVE_S3_FORCE_PATH_STYLE=1`)를 넣습니다(.env.example의 주석 블록). 버킷은 미리 만들어 두세요(MinIO 관리 화면 또는 아래 테스트가 `peerchive-test`를 만듦). web·worker는 같은 값을 읽습니다.
- 통합 테스트: 아래 변수가 있을 때만 실행되고 없으면 건너뜁니다. 주소는 루프백만 받습니다(실제 버킷·메일 서버 보호).

  ```sh
  DATABASE_URL=postgres://peerchive:peerchive@localhost:5432/peerchive \
  PEERCHIVE_TEST_MAILPIT_SMTP_URL=smtp://127.0.0.1:1025 PEERCHIVE_TEST_MAILPIT_API_URL=http://127.0.0.1:8025 \
  PEERCHIVE_TEST_S3_ENDPOINT=http://127.0.0.1:9000 PEERCHIVE_TEST_S3_ACCESS_KEY_ID=peerchive-local PEERCHIVE_TEST_S3_SECRET_ACCESS_KEY=peerchive-local-only \
  pnpm test
  ```

  - Mailpit: `apps/web/test/mail-smtp.integration.test.ts`(한국어 text+HTML·헤더·가린 로그, 매직링크 `/auth/verify#token=` 수신 후 로그인, 토큰이 로그에 없음; 매직링크 부분은 DATABASE_URL도 필요).
  - MinIO: `packages/files/test/s3-storage.test.ts`(저장소 공통 계약 테스트를 filesystem과 같이 실행: 키 검사·크기 한도·SHA-256·범위 읽기·덮어쓰기 move·목록 페이지·멱등 삭제), `apps/web/test/artifacts-s3.integration.test.ts`(업로드 → worker 검사 → clean → 내려받기, DATABASE_URL도 필요). 테스트마다 무작위 prefix를 쓰고 끝나면 지웁니다.
- 끝나면 `docker compose --env-file .env -f ops/docker-compose.yml --profile mailpit --profile minio stop mailpit minio`.

## 그 밖의 명령

| 명령 | 내용 |
|---|---|
| `pnpm typecheck` | 모든 워크스페이스 타입 검사(web은 `nuxt typecheck`) |
| `pnpm build` | web 프로덕션 빌드(`apps/web/.output`) |
| `pnpm worker` | worker 개발 실행(`NODE_ENV=development`, 루트 `.env` 읽음). 배포용은 `pnpm --filter worker start`(production 기본, 실제 검사기 필요). SIGINT/SIGTERM이면 진행 중인 작업을 기다린 뒤(최대 30초) 종료 |
| `pnpm bot` | 디스코드 봇 개발 실행(`NODE_ENV=development`, 루트 `.env` 읽음). 처음엔 `pnpm --filter bot register-commands`로 슬래시 명령 등록. 배포용은 `pnpm --filter bot start` |
| `pnpm db:generate` | `packages/db/src/schema.ts` 변경을 SQL migration으로 생성 |
| `pnpm --filter @peerchive/db grant-operator <email> [--revoke]` | 운영자 부여·회수(로그인한 적 있는 활성 사용자, 감사 이벤트 기록). 운영자 권한은 이 CLI로만 바꿉니다. `DATABASE_URL`(없으면 루트 `.env`) 사용 |
| `pnpm --filter worker backfill-strip [--dry-run] [--batch=100]` | 일회성: 메타데이터 제거 기능 전에 clean이 된 이미지의 메타데이터를 지우고 PDF 문서 속성 점검 결과를 채웁니다([ADR 0007](../docs/adr/0007-file-storage-and-scanning.md) "메타데이터 제거"). 멱등이며 웹·worker와 같은 `DATABASE_URL`·`PEERCHIVE_STORAGE_*`를 읽습니다(로컬은 `NODE_ENV=development`를 앞에 붙임). 처리 전 이미지는 공개 후보(422 `metadata_not_stripped`)·공개 조회(404)에서 빠집니다. 실패가 있으면 종료 코드 1 |
| `pnpm ops:reapply-deletions [--ledger-file=<path>] [--dry-run]` | 복구한 DB(`DATABASE_URL`)·저장소(`PEERCHIVE_STORAGE_*`)에 삭제 장부를 다시 적용(장부의 HMAC과 맞는 사용자를 다시 정리, 두 번 돌려도 같음). 파일을 주면 그 장부를 대상 장부에도 넣음. 출력은 개수만. 끝나기 전에는 점검 모드를 풀지 마세요 |
| `pnpm ops:export-ledger --out=<path>` | 삭제 장부를 JSON lines로 내보내기(개인정보 없음, 이미 있는 파일은 덮어쓰지 않음) |
| `ops/backup.sh` / `ops/restore.sh` / `ops/restore-drill.sh` | 백업 / 복구(`--from --target-db --storage-dir [--force]`) / 복구 연습(임시 DB, 단계별 시간). [runbook §3.3·§5·§6](../docs/ops/RUNBOOK.md) |
| `pnpm check:archive` | 원본 아카이브 보존 검증(`python3 scripts/check_archive.py`) |

스키마는 migration으로만 바꿉니다. `schema.ts`를 고쳤다면 `pnpm db:generate`로 생성한 SQL을 함께 커밋하세요(CI가 불일치를 검사합니다).

0008 migration은 `CREATE EXTENSION IF NOT EXISTS pg_trgm`으로 시작합니다. 관리형 PostgreSQL에서는 pg_trgm이 허용되어 있어야 하고 migration 계정에 확장을 만들 권한이 있어야 합니다(없으면 관리자가 미리 만들어 두세요).
