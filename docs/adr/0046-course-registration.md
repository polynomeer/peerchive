# 0046. 이번 학기 과목 등록: (사용자, 개설 학기) 한 행 + 지금·다음 학기만 + 본인만 보는 목록(감사·분석·소셜 경로 0건) + 5명 미만이면 없는 허브 수강 인원 + 등록에서 만드는 과제 공간(기존 학기·엠바고 규칙) + 등록 행에 시각을 채우는 학기 종료 알림

- 상태: 채택
- 날짜: 2026-11-02

## 맥락

E-01은 DELIVERY_PLAN §4.4 P1 보완 백로그의 첫 항목입니다: "학교·과목 검색으로 직접 등록(크롤링·연동 없음), 등록 정보는 본인만(공개 프로필·검색 0건), 홈에 과목별 허브·선배 노트·플랜 포크 진입점, 등록 과목에서 과제 공간을 만들면 과목·학기·엠바고 자동 채움, 허브의 “이번 학기 수강 중 N명”은 n ≥ 5일 때만, 학기 종료 후 선배 노트·공개 제안 알림". 관련 설계와 앞선 결정:

- PROOFU_EVOLUTION_PLAN §8.7(학기 초 등록, 과목 허브를 찾아오게 하는 대신 먼저 건네는 경로, 본인만, 학기 종료 알림), §8.6(허브 단계적 개방은 "등록한 학생"에게 준비 중 안내 — E-02), §8.8(팀원 찾기의 "같은 과목을 등록한 학생").
- ADR 0010(카탈로그: 정본·병합, 학기 종료 시각은 서버가 계산, 프로젝트 엠바고 단조 규칙), 0013(과목 허브·선배 노트·플랜 포크, "과목 등록은 구현하지 않음"), 0024(모집: 과목 등록이 없어 "같은 과목을 등록한 학생" 대신 "그 과목 학교 인증 사용자"가 과목 모집을 봄), 0027(5 미만 가림 `suppressSmall`), 0029(S-02 정체성 경계: 모듈 의존 lint·social DB 역할·속성 테스트).

## 결정

### 1. 데이터: `course_registrations` = (사용자, 개설 학기)

- 열: `user_id`, `course_term_id`(개설 학기가 과목을 정하므로 과목 id를 따로 두지 않음), `post_term_prompted_at`, `prompt_dismissed_at`(check: 알림 없이 닫힘 없음), `created_at`. (사용자, 개설 학기) unique.
- 스키마 구역은 "이번 학기 과목 등록"(커뮤니티 구역 아님). social DB 역할에 권한을 주지 않습니다(S-02 테스트가 확인).
- 과목 병합(ADR 0010)으로 개설 학기가 합쳐지면 같은 트랜잭션에서 등록을 정본 학기로 옮기고, 같은 사람이 이미 정본 학기에 등록했으면 원본 쪽 행을 지웁니다(감사 metadata `registrationsRepointed`). 학기가 정본 과목으로 옮겨질 뿐이면 등록은 그대로 따라갑니다. 읽기도 정본 학기(`loadCanonicalTerm`)로 풉니다.

### 2. 등록: 카탈로그에 있는 과목, 지금·다음 학기만

- `POST /api/v1/me/course-registrations {courseId, year, semester}` → 201. 과목은 카탈로그에 있어야 하고(없으면 422 `courseId: not_found`), 병합된 id면 정본으로 등록합니다. 크롤링·다른 서비스 계정 연동은 없습니다. 등록 화면(`/me/courses`)은 학교 → 과목 검색만 하고, 목록에 없는 과목은 과제 만들기의 과목 고르기(T-10)에서 먼저 추가하도록 안내합니다.
- **학기**: 지금 학기와 다음 학기만(`registrableTerms`, 아니면 422 `term: not_registrable`). 학기 구간은 카탈로그의 종료 규칙(`semesterEndsAt`)과 같은 서울 달력 경계 — 1–2월 전년도 겨울 계절학기, 3–6월 1학기, 7–8월 여름 계절학기, 9–12월 2학기. 다음 학기를 허용해 학기 직전(2월 말·8월 말)에 미리 등록할 수 있습니다.
- 그 학기의 개설 학기 행이 없으면 만들되 **만든 사람을 남기지 않습니다**(`ensureCourseTermUnattributed`: `created_by` null, 감사 `course_term.create`의 actor null, metadata `via: 'registration'`). 일반 학기 만들기(`createCourseTerm`)는 만든 사람을 감사에 남기므로, 그대로 쓰면 "이 사람이 이 과목·학기를 등록했다"가 운영자 기록에 드러납니다.
- 409 `already_registered`(같은 개설 학기), 409 `limit_reached`(학기당 15개), 429(사용자별 시간당 60회, 등록·지우기 합산).
- **감사 기록·분석 이벤트를 남기지 않습니다.** 등록은 본인만 보는 정보이고 운영자에게 사람별 등록을 보여 줄 이유가 없습니다.

### 3. 본인만: 목록·지우기·알림 닫기

- `GET /api/v1/me/course-registrations` → `{items, registrableTerms}`: 학교·과목·정본 학기·단계(`current`/`upcoming`/`ended`, 끝남은 개설 학기의 `ends_at` — 운영자가 고친 값 — 으로 판정)·알림 여부·이 학기에 연결된 내 과제(active 멤버, 스터디 기록 제외).
- `DELETE /api/v1/me/course-registrations/:id`(행 삭제, 기록 없음), `POST …/:id/dismiss-prompt`(멱등, 알림이 아직 없으면 409 `no_prompt`). 남의 id는 모두 404.
- **경계**: 등록 테이블·모듈에 닿는 서버 파일은 허용 목록(등록 모듈·허브 집계·병합·과제 만들기 라우트·`/me/course-registrations` 라우트)뿐이고, 운영자 라우트는 하나도 없습니다. 소셜 모듈·프로필/페르소나 라우트·공개 프로필/포트폴리오 경로에서 import로 닿는 파일 중 등록에 닿는 것은 익명 집계 함수(`enrollment-count.ts`)뿐입니다(S-02 lint 확장). 서비스 테스트는 등록한 두 사람의 공개 프로필·검색 결과·피드·팔로우 추천에 등록 id·과목 id·과목 이름·학기 id가 0건이고, 같은 과목 등록만으로는 추천되지 않으며(추천은 과제·학교 인증·관심 직무만 봄), 감사 기록에 등록 흔적이 없음을 확인합니다.

### 4. 홈의 과목별 진입점

- 로그인한 사람의 홈(`/`)에 "이번 학기 과목": 끝나지 않은 학기의 등록마다 **과목 허브**(`/c/:courseId`), **선배 노트**(`#hub-notes`), **플랜 포크**(`#hub-cases` — 포크는 공개 사례 페이지에서 함), **이 과목으로 과제 공간 만들기**(`/projects?registration=:id`). 화면이 뜬 뒤 클라이언트에서 불러옵니다.
- 허브는 아직 단계적 개방(E-02) 전이라 언제나 열립니다. E-02가 "준비 중"을 더하면 이 진입점이 그 안내로 이어집니다.

### 5. 등록 과목에서 과제 공간 만들기

- `POST /api/v1/projects {courseRegistrationId, title, kind, …}`: 내 등록이면 그 정본 개설 학기로 **기존 과제 만들기(`createProject`)를 그대로** 부릅니다. 과목·학기 연결과 엠바고(학기 종료까지, 단조 규칙)·감사·분석이 T-10 규칙 그대로입니다. 남의 등록·없는 id는 422 `courseRegistrationId: not_found`(존재를 드러내지 않음), `courseTermId`를 함께 보내면 422 `courseTermId: not_allowed`.
- 화면은 등록의 학교·과목·학기·엠바고 종료일을 고정 표시로 보여 주고 제목을 "<과목> 과제", 형태를 팀으로 미리 채웁니다. "다른 과목 고르기"를 누르면 기존 과목 고르기로 돌아갑니다.

### 6. 허브의 "이번 학기 수강 중 N명"

- 공개 허브 응답에 `enrollment: {termLabel, count} | null`. 정본 과목(+ 그 과목으로 병합된 과목)의 **지금 학기**(달력) 개설 학기에 등록한 active 계정의 서로 다른 사용자 수이고, 5명 미만이면 null이라 화면에 아무것도 없습니다(ADR 0027과 같은 기준, `enrollmentCountForHub`). 다음 학기 등록·탈퇴 요청 계정은 세지 않습니다. 사람 id·등록 시각은 싣지 않습니다.

### 7. 학기 종료 알림: 등록 행의 시각, worker가 한 번

- 주기 작업 `course-term-prompts`(기본 매시 53분, `PEERCHIVE_CRON_COURSE_TERM_PROMPTS`): 정본 개설 학기의 `ends_at`이 지난 등록 중 `post_term_prompted_at is null`인 것을 배치(설정 `batchSize`)로 골라 시각을 채웁니다. 조건부 갱신이라 여러 worker·재시도·수동 실행이 겹쳐도 등록마다 한 번이고, 닫은 알림은 다시 생기지 않습니다. active 계정만.
- 홈은 닫지 않은 알림마다 "선배 노트를 남겨 주세요"(`/senior-notes?course=`)와, 이 학기에 연결된 내 과제가 있으면 "공개할까요?"(과제의 공개 준비 화면, 팀 동의를 거침)를 보여 주고 "알림 닫기"를 둡니다. **메일·푸시는 없습니다**(화면 안 알림뿐).
- 새 알림 테이블을 만들지 않고 등록 행에 시각을 둡니다. 알림이 등록과 1:1이고, 등록을 지우거나 탈퇴하면 알림도 함께 사라집니다. 커뮤니티 알림(`community_notices`)은 커뮤니티 플래그·공간 규칙에 묶여 있어 쓰지 않았습니다.

### 8. 삭제

- 본인이 지우면 행 삭제. 탈퇴 정리(`account-purge`)가 그 사람의 등록을 지우고 삭제 장부에 `course_registrations` 개수를 남깁니다(재적용 idempotent).
- 기능 플래그는 두지 않습니다(P1, 공개로 넓혀지는 값이 5 미만 가림 집계뿐).

### 상태 코드 요약

| 경로 | 성공 | 오류 |
|---|---|---|
| `GET /me/course-registrations` | 200 | 401 |
| `POST /me/course-registrations` | 201 | 422 형식·`term: not_registrable`·`courseId: not_found`, 409 `already_registered`·`limit_reached`, 429 |
| `DELETE /me/course-registrations/:id` | 200 `{removed: true}` | 404, 429 |
| `POST /me/course-registrations/:id/dismiss-prompt` | 200 | 404, 409 `no_prompt` |

## 결과

- 학기 초에 과목을 고르면 홈에서 허브·선배 노트·포크·과제 공간 만들기로 바로 갑니다. 과제 공간은 기존 규칙으로 학기·엠바고가 걸립니다.
- 등록은 본인 화면과 5명 이상 익명 집계 밖으로 나가지 않고, 운영자 기록(감사·카탈로그 만든 사람)에도 남지 않습니다.
- migration `0043_course_registrations`(새 테이블 하나, enum 추가 없음, 빈 DB 처음부터 migrate 확인).
- 한계: 허브 수강 인원은 요청마다 셉니다(인덱스 `course_term_id`). 다음 학기 등록은 그 학기가 시작되기 전까지 허브 수에 들어가지 않습니다. 학기 경계는 달력이라 학교마다 다른 개강일을 반영하지 않습니다(종료는 운영자가 고친 `ends_at`을 따름). 카탈로그에 없는 과목은 등록 화면에서 바로 만들 수 없습니다(과제 만들기의 과목 고르기에서 추가). 모집(C-07)의 "같은 과목을 등록한 학생"으로 바꾸는 일과 허브 단계적 개방의 "등록 학생에게 준비 중"은 E-02·후속에서 이 테이블을 읽어 붙입니다.

## 대안

- **(사용자, 과목, 연도, 학기)로 저장**: 개설 학기 행 없이도 등록할 수 있지만, 과제 공간 만들기·엠바고·병합이 모두 개설 학기에 기대므로 결국 학기 행을 찾아야 하고 병합 때 옮길 것이 늘어납니다.
- **등록할 때 일반 `createCourseTerm` 재사용**: 코드가 가장 적지만 만든 사람이 감사에 남아 운영자가 사람별 등록을 추정할 수 있습니다.
- **별도 알림 테이블(내 알림 목록)**: 다른 알림 종류에도 쓸 수 있지만 지금은 종류가 하나이고, 등록과 같은 수명이라 행에 시각을 두는 편이 지우기·멱등성이 단순합니다.
- **읽을 때 계산하는 알림(학기가 끝났으면 바로 표시)**: worker가 필요 없지만 "학기가 끝나면 알림을 보냄"이라는 한 번의 사건이 없어 닫기·재표시 규칙과 나중의 메일 연결이 어렵습니다.
- **모든 학기 등록 허용**: 지난 과목을 기록하는 데 쓸 수 있지만 "이번 학기" 목적과 허브 수강 인원의 뜻이 흐려집니다. 지난 과목은 선배 노트·과제 공간으로 남깁니다.
- **수강 인원을 정확한 수 대신 구간으로**: 더 거칠어 안전하지만 5명 이상이면 정확한 수도 개인을 특정하지 못하고(§11.2와 같은 기준) 구간 설계가 따로 필요합니다.
