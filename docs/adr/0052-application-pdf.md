# 0052. 지원용 PDF: 공개 프로필 DTO 하나로 서버가 만드는 A4 PDF(`GET /api/v1/public/profiles/:handle/portfolio.pdf`) + 순수 JS(pdf-lib + @pdf-lib/fontkit)·한글 글꼴 Pretendard Regular(OFL) 부분 집합 + 지금 볼 수 있는 대표 케이스만·근거 절대 주소와 링크 + 메타데이터 제목만(작성자 없음) + 늘 noindex·no-store·첨부 + IP마다 분당 10회·프로필마다 분당 30회 + 숨긴·없는 프로필 404, 운영 스위치 503, 저장 없음, 플래그 없음

- 상태: 채택
- 날짜: 2026-11-02

## 맥락

E-08은 DELIVERY_PLAN §4.4 P1 보완 백로그 항목입니다: "서버 생성 PDF(인쇄 보기와 같은 공개 DTO만), 근거 링크 포함, 연결 꺼진 페르소나 정보 0건(S-01), 생성 rate limit". 제품 기획 §10.6은 "기본 인쇄 보기(MVP)"와 "지원용 PDF 개선(P1)"을 나눕니다. 관련 결정:

- ADR 0008(동료평가 리포트는 인쇄용 HTML + 브라우저 "PDF로 저장", 서버 PDF 없음). 대안에서 PDF 라이브러리를 "한글 글꼴 내장(수 MB)과 두 번째 렌더러 유지" 때문에 뺐습니다.
- ADR 0014(T-14 공개 프로필·인쇄 보기 `/u/:handle/print`·README 카드는 같은 공개 DTO만 그림), 0012(공개 조회 공통 handler: no-store·nosniff·no-referrer·noindex 기본·운영 스위치), 0028(S-01 페르소나·연결 플래그), 0031(S-03 과제 수행 목록), 0034(S-06 소셜 링크), 0050(E-06 "물어보면 좋은 질문"), 0051(E-07 공유 링크: 공개 프로필보다 좁은 DTO).
- 브라우저 인쇄는 브라우저마다 쪽 나눔·머리글·글꼴이 달라 지원서에 붙일 파일 모양이 일정하지 않고, 모바일에서는 "PDF로 저장"을 찾기 어렵습니다.

## 결정

### 1. 내용: 공개 프로필 DTO만

- 렌더러 `renderPortfolioPdf(dto, {font, origin, now})`(`server/modules/portfolio/pdf.ts`)는 **DB를 읽지 않고** `getPublicPortfolioProfile`의 응답(공개 프로필 JSON·인쇄 보기가 쓰는 것과 같은 객체)만 받습니다. 그래서 공개 프로필에 없는 정보(이메일·내부 id·비공개 기록·답변 메모·연결을 끈 상대 페르소나)는 PDF에 들어갈 길이 없고, 게시 취소·숨김·철회·대체·엠바고·계정 상태 판정도 공개 프로필과 같습니다.
- 순서는 인쇄 보기와 같습니다: 이름 @handle(표시명이면 "표시명 프로필") → 연결을 켠 상대 페르소나(`linkedPersona`가 있을 때만 이름·주소) → 관심 직무·졸업 → 학교(본인 입력)·학교 인증 배지 → 한 줄 소개 → 구직 여부·연락 정책 문구 → 온라인 프로필 주소 → 소셜 링크(`링크 확인됨` 설명 포함) → 대표 케이스 → 역량 × 근거 → 역량과 스킬 → 과제 수행 목록(DTO에 있을 때, 전체 공개) → 과제 타임라인 → 안내.
- **대표 케이스는 지금 볼 수 있는 것(`available`)만** 싣고, 볼 수 없는 케이스는 "볼 수 없습니다" 안내도 싣지 않습니다(지원 서류에 빈 칸을 남기지 않음). 케이스마다 제목, 직무 관점·학기·공개 버전·사례 속 본인 표시, 원본 공개 사례 주소, 구역별 문장(본인 회고 표시)과 문장마다 근거(출처 이름 + 절대 주소).
- "이 지원자에게 물어보면 좋은 질문"(E-06)은 **싣습니다**. 학생이 공개로 고른 질문 글만 DTO에 있고(실명 페르소나·볼 수 있는 케이스), 공개 프로필·인쇄 보기와 같은 판단입니다. 답변 메모는 DTO에 없습니다.
- 역량 × 근거는 표 대신 역량마다 "케이스 제목: 종류별 개수" 줄과 근거 주소로 요약합니다(볼 수 없는 케이스 칸은 뺌, 점수·수준 없음). 후배 기여 개수·팔로우 수는 인쇄 보기처럼 싣지 않습니다.
- 근거 주소 = `NUXT_SITE_ORIGIN` 첫 항목 + DTO의 경로(`/p/<slug>#…`). 주소 줄에는 URI 링크 주석을 붙여 PDF 뷰어에서 누를 수 있습니다.
- 바닥글: 쪽마다 "<이름> 포트폴리오 · n / N", 끝에 "원본 사례가 철회되면 온라인 프로필에서 바로 닫히지만 이미 내려받은 PDF는 회수되지 않습니다"와 생성 날짜(서울)·판 버전.
- 메타데이터: 제목 = "<표시 이름> 포트폴리오", Creator·Producer = Peerchive, 언어 ko-KR, 생성 시각. **작성자·주제·키워드는 비웁니다**(이메일·id 없음, pdf-lib 기본 Producer도 덮어씀).

### 2. 조판·글꼴: 순수 JS, 부분 집합

- `pdf-lib` 1.17.1(MIT) + `@pdf-lib/fontkit` 1.1.1(MIT). 의존: `@pdf-lib/standard-fonts`·`@pdf-lib/upng`·`pako`·`tslib`(모두 MIT, pako는 MIT·Zlib). 네이티브 모듈·설치 스크립트·headless Chromium 없음. pdfkit은 표준 글꼴 AFM을 `__dirname` 기준 파일로 읽어 nitro 번들과 맞추기 번거로워 고르지 않았습니다.
- 글꼴: **Pretendard Regular TTF 1.3.9**(SIL OFL 1.1, 한글 11,172자 포함, 2.7MB) 하나를 고치지 않은 원본 그대로 `apps/web/server/assets/fonts/Pretendard-Regular.ttf`에 두고, 라이선스 전문을 같은 폴더 `Pretendard-OFL.txt`에 둡니다. PDF에는 쓴 글자만 부분 집합으로 넣고(보통 수십 KB) ToUnicode 표가 함께 들어가 글을 복사·검색할 수 있습니다. 굵은 글꼴은 크기 때문에 넣지 않고 글자 크기로 위계를 줍니다.
  - OTF(CFF, 1.5MB)는 @pdf-lib/fontkit 1.1.1의 부분 집합 만들기가 실패해("Not a CFF Font") TTF를 씁니다.
  - **fontkit 부분 집합 버그 회피**: 부분 집합의 glyf가 0xffff 이하이면 짧은 loca(오프셋/2)로 쓰는데, 원본 글리프 길이가 홀수이면 그 뒤 글리프의 오프셋이 어긋나 뷰어에서 글자가 빈칸으로 그려집니다(ToUnicode는 맞아서 글 추출만으로는 드러나지 않음, macOS 렌더링으로 확인). 렌더러는 fontkit을 감싸 부분 집합에 글리프를 넣을 때마다 짝수 길이로 0 한 바이트를 채웁니다(글꼴 파일은 바꾸지 않음). 단위 테스트가 넣은 글리프를 원본 글꼴의 조판 결과와 비교해 회귀를 막습니다.
- 글꼴에 없는 글자: 그림 문자(출처 이름의 🧱·⚖️ 등, 이음·이체 선택자 포함)는 빼고, 그 밖(한자 등)은 `?`로 바꿉니다. 글은 NFC로 맞추고 공백을 한 칸으로 모읍니다.
- A4(595.28 × 841.89pt), 단어 단위 줄바꿈(한 단어가 줄보다 길면 — 주소 등 — 글자 단위), 글머리표 둘째 줄 들여쓰기, 제목이 쪽 끝에 홀로 남지 않게 미리 쪽을 넘김.
- nitro 서버 자산: 글꼴은 `server/assets/`(`useStorage('assets:server')`)로 읽어 빌드 결과 서버 번들에 들어가고, 공개 정적 파일(`public/`)로는 나가지 않습니다. 프로세스마다 한 번 읽어 둡니다(`server/utils/pdf-font.ts`, 실패하면 다음 요청에서 다시).

### 3. 경로·헤더·한도

- `GET /api/v1/public/profiles/:handle/portfolio.pdf`(로그인 불필요, 세션을 읽지 않음, 쿠키 없음). 공개 조회 공통 handler 위에서 동작하므로 no-store·nosniff·`Referrer-Policy: no-referrer`·운영 스위치(`PEERCHIVE_PUBLIC_READS_DISABLED`, 미들웨어와 handler 양쪽) 503·404 정규화가 같습니다. 여기에 **설정과 무관하게 늘** `X-Robots-Tag: noindex, nofollow`, `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="<handle>-portfolio.pdf"`, `Content-Security-Policy: sandbox; default-src 'none'`, `Cross-Origin-Resource-Policy: same-origin`.
- 없는 handle·비활성 계정·운영 조치로 숨긴 프로필은 공개 프로필과 같은 404이고 PDF를 만들지 않습니다.
- **생성 한도**(`rate_limit_buckets`, 고정 창): IP마다 분당 10회(`portfolio_pdf_ip`, 프로필을 읽기 전에 셈 — 없는 handle도 셈), 프로필(handle)마다 분당 30회(`portfolio_pdf_handle`, 있는 프로필만 — 없는 handle로 버킷을 늘리지 않음). 초과는 429 `rate_limited`. 한 번 만드는 데 보통 0.1~0.3초(글꼴 해석 + 조판)라 공개 JSON보다 비싸서 따로 셉니다. 프로필 한도는 여러 IP로 한 사람의 PDF를 막을 수 있지만, 온라인 프로필·인쇄 보기는 그대로이고 다음 분에 풀립니다.
- 저장·캐시 없음: 요청마다 그 시점 공개 DTO로 만들고 서버에 사본을 남기지 않습니다(철회가 다음 요청부터 반영). 생성 기록·감사·분석 이벤트도 없습니다(누가 받았는지 추적하지 않음).
- 화면: 공개 프로필 `/u/:handle` 머리글과 인쇄 보기 도구 막대에 "PDF 내려받기" 링크. 인쇄 보기(브라우저 "PDF로 저장")는 그대로 둡니다.

### 상태 코드 요약

| 경로 | 성공 | 오류 |
|---|---|---|
| `GET /api/v1/public/profiles/:handle/portfolio.pdf` | 200 `application/pdf` 첨부 | 404(없음·숨김·비활성), 429 `rate_limited`, 503 `public_reads_disabled` |

## 결과

- 검토자·학생은 로그인 없이 공개 프로필에서 한 번에 A4 PDF를 받아 지원서에 붙입니다. 문장마다 공개 기록 주소가 있어 종이·PDF에서도 근거를 따라갈 수 있습니다.
- 표시명 페르소나 PDF에는 대표 케이스·타임라인이 없고(공개 프로필과 같음), 연결을 끄면 상대 페르소나의 이름·handle·소개·주소가 어느 쪽 PDF에도 없습니다.
- 추가 바이너리 약 2.7MB(글꼴) + 라이선스 4KB. migration 없음, 플래그 없음(이미 공개된 프로필을 다른 형식으로 보여 줄 뿐 공개 범위를 넓히지 않음).
- 테스트: web 단위 `portfolio-pdf.test.ts`(`%PDF-`·A4·메타데이터·한글 추출·근거 절대 주소와 링크 주석·볼 수 없는 케이스 제외·그림 문자 제거·긴 글과 주소 줄바꿈·여러 쪽·부분 집합 글리프가 원본과 같은지), web 통합 `portfolio-pdf.integration.test.ts`(공개 DTO와 같은 케이스·근거 주소, 철회 케이스·답변 메모·이메일·id 0건, 헤더·쿠키 없음, S-01 양방향, 숨김·정지·없는 handle 404, 운영 스위치 503, IP·프로필 한도), e2e `e08-portfolio-pdf.spec.ts`(공개 프로필에서 내려받기 → `%PDF-`·application/pdf·첨부·noindex). 테스트의 글 추출은 새 의존성 없이 pdf-lib로 PDF를 다시 읽어 ToUnicode 표로 되돌립니다(`test/pdf-text.ts`).
- 한계: 글꼴이 Regular 하나라 굵은 글씨가 없습니다. 한자·그림 문자는 `?`·생략으로 나옵니다. 오른쪽 맞춤·표 조판은 하지 않습니다. 공유 링크(E-07) 페이지의 PDF는 만들지 않았습니다(공유 DTO가 더 좁아 같은 렌더러를 쓸 수 있지만 토큰 경로의 한도·헤더를 따로 정해야 함). 내려받은 PDF는 철회해도 회수되지 않습니다(바닥글에 안내).

## 대안

- **headless Chromium으로 인쇄 보기를 PDF로**: 화면과 모양이 같지만 이미지·메모리·보안 격리 부담이 크고(ADR 0008과 같은 판단), 백로그 조건(순수 서버 생성)과도 맞지 않습니다.
- **pdfkit**: 글 흐름·줄바꿈이 내장되어 조판 코드가 줄지만, 표준 글꼴 AFM 파일을 런타임에 디스크에서 읽어 nitro 번들 확인이 더 필요합니다.
- **Noto Sans KR**: 같은 OFL이지만 배포 TTF(가변·CJK 포함)가 Pretendard Regular보다 커서 추가 바이너리 예산(약 6MB)에 여유가 적습니다.
- **글꼴을 미리 부분 집합으로 잘라 저장(KS X 1001 2,350자 등)**: 파일은 작아지지만 드문 음절(똠·뷁 등)이 빠지고, OFL의 예약 글꼴 이름 때문에 고친 글꼴은 이름을 바꿔야 합니다.
- **글꼴 전체를 PDF에 넣기(부분 집합 없음)**: fontkit 버그를 피하지만 PDF 하나가 1MB를 넘습니다.
- **볼 수 없는 케이스를 안내 문구로 남김**: 화면과 같지만 지원 서류에 빈 사례가 남고, 철회 사실을 PDF 사본에 굳힙니다.
- **본인만 내려받기(로그인 경로)**: 공개 프로필을 이미 누구나 보므로 막을 이유가 작고, 검토자가 직접 받을 수 없습니다.
