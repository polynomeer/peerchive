# 0059. AI 케이스 다듬기: 서버 AI 설정(ADR 0057 `features.ai`)이 있을 때만 + 케이스 주인이 "AI로 다듬기"를 누를 때마다 한 번(누름 = 그 한 번의 동의, 따로 켜 두는 설정 없음) → 보내는 근거는 케이스가 고정한 release 스냅샷에서 **운영 조치로 가린 항목을 뺀 사본** 안의 공개 요약·케이스가 이미 인용한 항목·본인이 쓴 로그·참석한 회의·본인 역할 선언·마일스톤·본인이 올린 파일뿐(최대 60개·각 300자, 이름 대신 본인/팀) + 다듬을 문장은 본인 회고·가린 항목 인용 문장 제외 → Claude 구조화 출력 `{sentences[{id, text, citations[{kind,key}]}]}` → **보낸 근거에 없는 인용은 버리고 남은 인용이 없으면 `uncited`** → 케이스 version에 묶인 제안(`case_ai_polish_proposals`, 케이스마다 하나, 7일) → 학생이 지금 문장과 나란히 보고 문장마다 고쳐 받아들이기/버리기 → 받아들인 문장 `case_sentences.ai_generated`·케이스 `generator = 'ai'`(되돌리지 않음) + 출처 없는 AI 문장은 "본인 회고"로 바꿔도 게시 409·대표 지정 422 + 공개 DTO·프로필·인쇄·PDF "AI로 다듬음 · 다듬은 문장은 모두 근거 기록에 연결됨" + 케이스마다 하루 5번 + `@peerchive/ai` 상한·사용량 그대로

- 상태: 채택
- 날짜: 2026-11-02

## 맥락

E-14는 DELIVERY_PLAN §4.4 P1 보완 백로그의 마지막 항목입니다: "학생이 고른 공개 범위 안에서만, 모든 문장에 출처 로그 인용, 출처 없는 문장은 하이라이트되어 고치거나 지워야 발행, `generator = ai` 기록". 의존 항목은 T-13/T-14(케이스 스터디, ADR 0014)와 E-12(공용 AI 클라이언트, ADR 0057)입니다. 관련 설계와 앞선 결정:

- PROOFU_EVOLUTION_PLAN §10.2 표 P1 행("학생이 선택한 공개 범위 안에서만 AI가 문장을 다듬음. 모든 문장에 출처 로그가 붙고, 출처 없는 문장은 하이라이트되어 고치거나 지워야 발행 가능"), §15 AI 정책(생성물 표시·승인 필수, 비공개 데이터는 해당 팀 작업에만, 학습 미사용 API 조건, AI 없이도 핵심 기능 사용).
- ADR 0014: 케이스는 게시된 release 하나에 고정되고, 문장 인용은 그 스냅샷 안의 `{releaseVersion, kind: summary|log|claim|milestone|artifact, key}`, 출처 없는 문장은 게시 409 `uncited_sentences`(한계·회고 구역의 "본인 회고"만 예외), 스키마에 처음부터 `case_studies.generator`(check `in ('template')`, "AI 다듬기는 P1")가 있었습니다.
- T-15(운영 조치로 가린 항목은 공개 읽기에서 빼고, 그 항목을 인용한 케이스 문장은 공개 화면에서 자리 표시로 바꿈), ADR 0050(면접 준비 팩도 케이스 인용을 씀), ADR 0016(감사는 id·개수만, 탈퇴 정리), ADR 0057(`callAi`·`requireAiConfigured`·사용량·오류 503·프롬프트·출력 로그 없음), ADR 0058(같은 클라이언트 재사용).

## 결정

### 1. 켜짐과 동의

- **서버**: E-12와 같은 `aiConfigured()`(`PEERCHIVE_AI_ENABLED=on` + `ANTHROPIC_API_KEY`). 꺼져 있으면 새 경로 네 개 모두 404이고 편집 화면에 칸이 없습니다(`features.ai`). 템플릿 초안·편집·게시·대표 지정은 AI와 무관하게 그대로입니다(테스트). 새 플래그·환경 변수는 없습니다.
- **동의**: E-12는 과제마다 켜 두는 동의, E-13은 팀 전원 동의를 두었지만 E-14는 **케이스 주인이 버튼을 누르는 그 한 번이 동의**입니다. 근거가 이미 학생(과 팀원 동의)이 공개하기로 고른 release 스냅샷 글뿐이고, 결과는 학생이 문장마다 받아들이기 전에는 케이스를 바꾸지 않으며, 부를 때마다 학생이 직접 누르기 때문입니다. 화면 안내가 보내는 것과 표시 규칙을 누르기 전에 보여 줍니다. 팀원의 공개 글이 근거로 들어갈 수 있지만 그 글은 이미 그 팀원이 공개에 동의한 것이고, 케이스가 이미 인용한 것만 들어갑니다(§2).
- **쓸 수 있는 사람**: 케이스 주인만(다른 사람·같은 공개의 팀원에게는 404, 케이스 규칙 그대로). 원본을 더 이상 볼 수 없는 케이스는 409 `unavailable`.

### 2. AI에 보내는 것(이것뿐)

| 보냄 | 안 보냄 |
|---|---|
| 고정 system 프롬프트(상수, 캐시 대상), 직무 관점 라벨 | 비공개 작업 테이블(로그·체크인·할 일·초안), 공개 후보에 넣지 않은 로그 |
| 공개 요약(스냅샷의 공개 제목·학생 요약) | 다른 release(이전·다음 공개 버전)·다른 과제·다른 사람의 케이스 |
| 케이스 문장이 **이미 인용한** 스냅샷 항목 | 스냅샷 안이라도 케이스가 인용하지 않은 **팀원의** 로그·역할 선언·파일 |
| 본인이 쓴 로그, 본인이 참석한 회의 로그, 본인 역할 선언, 마일스톤, 본인이 올린 파일 | **운영 조치로 가린 항목**(가린 사본에서 고름), 가린 항목을 인용한 문장 |
| 항목마다 `kind`·`key`·"본인/팀" 표시와 스냅샷 글(태그별 주요 필드, 300자) | 사람 이름(스냅샷 표시 이름 포함)·사용자 id·이메일·과제 내부 이름·케이스 id |
| 다듬을 문장(본인 회고·가린 항목 인용 문장 제외)과 그 인용 | 본인 회고 문장(학생 자신의 말, 출처 없이 둘 수 있는 유일한 글) |

- 근거 목록은 domain `collectPolishEvidence`가 **스냅샷만 입력으로** 만듭니다(웹이 `redactSnapshot`으로 가린 항목을 뺀 사본을 넘김). 순서는 요약 → 이미 인용한 항목 → 본인 로그 → 참석 회의 → 본인 역할 선언 → 마일스톤 → 본인 파일, 최대 60개. "본인이 쓴 것"은 release의 비공개 참조(refs)에서 계산하지만 보내는 것은 참/거짓 표시뿐입니다.
- "학생이 고른 공개 범위"는 이 케이스가 고정한 release(학생이 공개 후보에서 고르고 팀원이 동의한 스냅샷)로 해석합니다. 그 안에서도 팀원 기록은 케이스가 이미 인용한 것만 보내 최소로 둡니다.
- 근거·문장은 `<evidence>`의 `<item kind key by>`·`<sentences>`의 `<s id section cites>` 안에 넣고 닫는 태그를 무력화합니다(`neutralizePromptText`). 키는 속성에 넣기 전 영숫자·`_`·`-`만 남깁니다. system 프롬프트는 구획 안 글을 지시로 따르지 않게 하고, 수치·성과·기술 이름을 지어내지 않고, 팀의 일을 본인 일처럼 쓰지 않게 합니다.
- 테스트가 가짜 공급자로 받은 글 전체에서 비공개 로그·다른 과제 로그·인용하지 않은 팀원 진행 로그·가린 로그의 표지 문자열과 키, 두 사람의 표시 이름, 사용자 id·이메일, 과제 id·내부 이름, 케이스 id가 0건임을 확인합니다.

### 3. 출력 검증과 `uncited`

- 출력 스키마 `{sentences: [{id, text, citations: [{kind, key}]}]}`, `feature: case_polish.suggest`, effort `medium`, max_tokens 16000(E-12 초안과 같은 근거: 문장 최대 60개·각 500자 JSON).
- domain `validatePolishOutput`: 모르는·중복 id는 버림, 글은 공백 정리 후 500자, 인용은 **보낸 근거 목록 안에 있는 `kind:key`만**(모르는 종류·없는 키·스냅샷에는 있지만 보내지 않은 키·가린 키는 버리고 수만 셈), 중복 제거·12개. **남은 인용이 없으면 `uncited: true`** — 버리지 않고 강조된 제안으로 남깁니다(학생이 출처를 붙여 살릴 수 있게). 글·인용이 지금과 같으면 제안하지 않습니다.
- 한 문장에 한 제안(합치기·나누기·새 문장 없음). 그래야 "지금 문장 ↔ 제안" 비교와 문장마다 받아들이기가 단순합니다.

### 4. 제안·받아들이기

- 제안은 `case_ai_polish_proposals`(케이스마다 하나, 새로 다듬으면 바꿈)에 `base_version`(케이스 version)·`suggestions[{section, index, text, citations[{kind,key}], uncited}]`만 둡니다. 근거 글·프롬프트는 저장하지 않습니다. 케이스를 편집 저장하면(version이 바뀜) 지우고, 다른 version·7일 지난 제안은 읽을 때 없는 것으로 봅니다(worker `ai-case-polish` 매시 29분이 지움).
- AI 호출은 트랜잭션 밖(`callAi`), 저장 직전에 케이스를 잠그고 version이 그대로인지 다시 확인합니다(바뀌었으면 409 `version_conflict`, 결과 버림).
- **받아들이기** `POST …/ai-polish/apply {expectedVersion, accept[{section, index, text?}]}`: 고른 제안만 그 자리 문장을 바꾸고(글을 고쳐서도, 1–500자), 나머지는 버립니다. 인용은 제안의 인용 중 지금도 (가린 항목을 뺀) 스냅샷에 있는 것만. 받아들인 문장은 `kind: evidence`·`ai_generated = true`, 케이스는 `generator = 'ai'`·version+1, 게시 중이었으면 초안으로(편집과 같은 규칙). 받아들인 것이 없으면 케이스는 그대로이고 제안만 지웁니다. 다른 version·없는 제안은 409 `no_proposal`.
- **고친 뒤에도 AI 문장인가**: 받아들일 때 고친 글은 AI 문장입니다(E-12 "고친 뒤 승인해도 `AI 초안`"과 같음). 이후 편집 저장에서는 domain `carryAiGenerated`가 **글이 그대로인** 이전 AI 문장에만 표시를 이어 붙입니다(구역을 옮겨도). 글을 고치면 학생 문장이 됩니다. 케이스의 `generator = 'ai'`는 한 번 되면 되돌리지 않습니다 — 쉼표 하나 고쳐 "AI로 다듬음" 표시를 지울 수 없게.

### 5. 게시 막힘(출처 없는 문장)

- domain `findUncitedSentences`: 출처 없는 문장은 기존대로 게시를 막고, 한계·회고 구역의 "본인 회고" 예외는 **AI 문장(`aiGenerated`)에는 적용하지 않습니다**. 그래서 출처 없는 AI 제안을 받아들인 뒤 "본인 회고"로 바꿔도 게시할 수 없습니다(고치거나 지워야 함).
- **게시** `POST /case-studies/:id/publish`: 기존 T-14 계약 그대로 409 `uncited_sentences` + `sentences[{section, index}]`. 백로그 설명은 422를 말했지만 템플릿 흐름의 기존 응답·화면을 바꾸지 않으려고 같은 코드를 씁니다. 문장은 편집 때마다 다시 쓰여 행 id가 안정되지 않으므로 "구역 + 구역 안 순서"가 문장 식별자입니다.
- **대표 지정**(판 만들기·미리보기 `resolveEdition`): 게시 중인 케이스만 고를 수 있어 정상 흐름에서는 생길 수 없지만, 서버가 한 번 더 확인해 422 `featuredCaseStudyIds.N: uncited_sentences` + `sentences[{caseIndex, section, index}]`로 막습니다(테스트는 게시 상태를 직접 만들어 확인).
- 화면: 편집 화면의 "출처 없음" 강조가 같은 규칙(AI 문장 표시 포함)을 따르고, 제안 목록은 `uncited` 제안을 강조하며 기본으로 체크하지 않습니다.

### 6. 공개 표시

- 작성자 DTO: `generator: 'template' | 'ai'`, 문장마다 `ai`. 공개 DTO(`PublicCaseStudyDto`, 공개 프로필·판 미리보기·제한 공유 링크가 같은 것을 씀)에 `generator` 하나만 더합니다(문장별 표시는 공개하지 않음 — 게시된 케이스의 모든 근거 문장은 이미 출처에 연결되어 있음).
- 문구 "**AI로 다듬음 · 다듬은 문장은 모두 근거 기록에 연결됨**"(domain `AI_CASE_POLISH_NOTE`)을 공개 프로필·인쇄 보기(`PortfolioView` 메타 줄 배지)와 PDF(메타 줄)에 붙입니다. E-12·E-13 로그의 `AI 초안` 배지처럼 출처를 숨기지 않되 감점 신호처럼 보이지 않게 메타 정보로 둡니다. "모든 문장"이 아니라 "다듬은 문장"이라고 쓴 것은 본인 회고가 출처 없이 남을 수 있기 때문입니다.

### 7. 한도·감사·보존

- 부르기 전에(넘으면 공급자 호출 0): 케이스마다 하루(UTC) 5번(`rate_limit_buckets`, 케이스 id 해시, 실패도 셈) → E-12 서버 전체 토큰·사용자·전체 하루 호출(`callAi`). 상태 응답에 오늘 남은 횟수를 줍니다.
- 거절은 503 `ai_declined`, 출력 상한·형식 오류·공급자 오류는 503 `ai_unavailable`, 아무것도 저장하지 않습니다(사용량만 `ai_usage_daily`, 기능 `case_polish.suggest`).
- 감사 `case_study.ai_polish {version, sentences, evidence, suggestions, uncited, droppedCitations}`·`ai_polish_apply {version, accepted, rejected, edited, uncited, unpublished}`·`ai_polish_discard {version, suggestions}` — 글 없음. 분석 이벤트는 더하지 않았습니다(enum 변경 없이 감사로 충분).
- 탈퇴 정리는 본인 제안을 케이스보다 먼저 지웁니다(외래 키). 받아들인 문장은 케이스 문장이라 케이스 규칙(ADR 0016)을 따릅니다.

| 경로 | 성공 | 오류 |
|---|---|---|
| `GET /api/v1/case-studies/:id/ai-polish` | 200 `CaseAiPolishStateDto {proposal, remainingToday, polishable}` | 404(AI 꺼짐·남의 케이스) |
| `POST …/ai-polish {expectedVersion}` | 200 상태(새 제안) | 404, 409 `unavailable`·`version_conflict`·`nothing_to_polish`, 429, 503 `ai_declined`·`ai_unavailable` |

## 결과

- 서버에 키가 있으면 학생은 케이스 편집 화면에서 템플릿 문장을 읽기 좋은 문장으로 다듬은 제안을 받아, 지금 문장과 나란히 보고 고르고 고쳐 받아들일 수 있습니다. 근거에 연결되지 않은 AI 문장은 강조되고 게시·대표 지정이 막히며, 공개 화면에는 "AI로 다듬음" 표시가 남습니다. AI가 없으면 아무것도 달라지지 않습니다.
- migration `0054_ai_case_polish`(테이블 `case_ai_polish_proposals`, `case_sentences.ai_generated`, `case_studies_generator_check`를 지우고 `in ('template', 'ai')`로 다시 만듦 — 열은 enum이 아니라 text + check, 빈 DB 처음부터 migrate 확인), domain `ai-case-polish.ts`(+ `findUncitedSentences` AI 문장 규칙), 웹 `server/modules/ai/case-polish.ts`, 경로 네 개, 화면 `CaseAiPolish.vue`·편집 화면 "AI 문장" 표시, 공개 `generator`·`PortfolioView`·PDF 표시, 판의 대표 지정 확인, worker 작업 `ai-case-polish`·탈퇴 정리. 새 의존성 없음.

## 대안

- **케이스마다 켜 두는 동의(E-12처럼)**: 한 번 켜면 계속 쓸 수 있지만, 매번 학생이 누르는 기능이라 켜기 단계가 같은 확인을 반복할 뿐입니다. 누름을 동의로 보고 화면 안내로 보낼 것을 먼저 보여 줍니다.
- **스냅샷 전체를 근거로 보냄**: AI가 더 많은 연결을 찾을 수 있지만 케이스가 인용하지 않은 팀원 기록까지 외부로 나갑니다. 이미 인용한 항목과 본인 항목으로 줄였습니다.
- **출처 없는 AI 문장을 서버가 버림**: 단순하지만 학생이 출처를 붙여 살릴 기회가 없어집니다. 기획서대로 강조해 남기고 게시만 막습니다.
- **AI가 케이스를 바로 고침(제안 없이)**: 빠르지만 "생성물 승인 필수"(§15)와 맞지 않습니다. 문장마다 받아들이게 합니다.
- **게시 오류를 422로 바꿈**: 백로그 문구와 맞지만 T-14의 409 `uncited_sentences` 계약·화면을 바꿉니다. 게시는 409 그대로, 새로 막는 대표 지정만 422(필드 오류)입니다.
- **문장마다 공개 표시**: 더 자세하지만 게시된 문장은 모두 출처에 연결되어 있어 정보가 적고 화면이 복잡해집니다. 케이스 단위 표시로 둡니다.
- **편집하면 `generator`를 template로 되돌림**: 학생 글이 된 케이스를 정확히 보이지만 작은 수정으로 표시를 지울 수 있습니다. 한 번 ai면 남깁니다.
