# 0008. 동료평가 리포트 형식: 인쇄용 HTML 페이지(브라우저 "PDF로 저장")

- 상태: 채택
- 날짜: 2026-10-20

## 맥락

PROOFU_EVOLUTION_PLAN §7은 학기 말 수업 동료평가 제출용 "팀원별 기여 요약 PDF"를 요구하고, SYSTEM_DESIGN §6.4는 `ContributionReport(project_id, period, generated_at, object_key)`를 초안으로 둡니다. T-08의 완료 조건은 확인 상태가 구분되어 나타나고 비공개 타 팀 데이터가 섞이지 않는 것입니다(DELIVERY_PLAN T-08, 시나리오 C).

서버에서 PDF를 만들려면 headless 브라우저(Chromium 수백 MB)나 PDF 조판 라이브러리와 한글 글꼴 내장이 필요하고, 만든 파일을 저장소에 두면 철회·삭제·권한 변경 때 함께 지워야 할 사본이 생깁니다.

## 결정

- 리포트는 **인쇄에 맞춘 HTML 페이지** `/projects/:id/report?from=&to=`입니다. 학생은 브라우저의 인쇄 → "PDF로 저장"으로 PDF를 만듭니다. 서버는 PDF를 만들지도 저장하지도 않습니다.
- 데이터는 장부 API `GET /api/v1/projects/:id/contribution`(멤버만, 비멤버 404) 하나에서 옵니다. 같은 정책 함수·같은 project_id 조건을 쓰므로 화면·리포트·주간 요약(T-09 봇)이 같은 범위를 봅니다. DTO에는 이메일·다른 프로젝트 자료가 없습니다(통합 테스트로 확인).
- 페이지에는 과제 이름, 기간(서울 날짜, 월~일 기본), 만든 시각, 상태 표시 설명, 멤버별 역할 선언(상태·팀원 응답·근거 제목)과 기간 기록의 종류별 개수, "※ 개수는 참고용이며 기여의 크기를 뜻하지 않습니다." 문장을 넣습니다. 점수·비율·순위는 없고 멤버는 이름순입니다.
- 인쇄 CSS: `@page { size: A4 }`, 사이트 머리글·도구 막대(`.no-print`) 숨김, 제목 뒤·선언·표 안에서 페이지가 나뉘지 않게(`break-after/inside: avoid`). 페이지는 사이트 레이아웃을 쓰지 않고 `noindex`입니다.
- `ContributionReport` 테이블(object_key)은 만들지 않습니다. 리포트는 요청 때마다 그 시점 데이터로 만들며, 만든 시각을 본문에 찍습니다.

## 결과

- 새 의존성이 없습니다. 한글 글꼴·조판은 사용자 브라우저가 맡습니다.
- 저장된 PDF 사본이 서버에 없으므로 철회·탈퇴·멤버 변경을 사본에 다시 적용할 필요가 없습니다. 학생이 내려받은 PDF는 회수할 수 없다는 점은 다른 내려받기와 같습니다.
- 브라우저마다 여백·머리글/바닥글(인쇄 대화상자 설정)이 조금 다릅니다. 브라우저의 "머리글과 바닥글" 옵션은 사용자가 끕니다.
- 알려진 한계(TODO):

## 대안

- 서버 PDF(Puppeteer/Playwright): 모양은 일정하지만 Chromium 이미지·메모리·보안 격리 부담이 크고 저장 사본 관리가 생깁니다.
- PDF 라이브러리(pdfkit 등): 한글 글꼴 내장(수 MB)과 직접 조판이 필요하고, 화면과 다른 두 번째 렌더러를 유지해야 합니다.
- CSV 내보내기: 개수만 남아 "종류와 근거" 원칙과 맞지 않고 동료평가 제출물로 쓰기 어렵습니다.
