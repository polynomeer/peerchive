# ADR 0060: S-·P2·E- 백로그의 미결 질문 결정

- 상태: 채택
- 날짜: 2026-11-04
- 관련: [ADR 0028](0028-personas.md)~[ADR 0059](0059-ai-case-polish.md)

## 맥락

S-01~S-07, I-01·I-02, A-01~A-07, E-01~E-14를 구현하며 제품 판단이 필요한 질문을 각 ADR과 작업 보고에 남겼습니다. 소유자가 2026-11-04에 "권장사항으로 결정하고 진행"하기로 했으므로, 권장안을 한곳에 확정합니다. 판단 기준은 다음 순서입니다.

1. 개인정보·정체성 분리를 지키는 쪽을 고릅니다.
2. 제품 기획·시스템 설계에 적힌 동작이 있으면 그대로 따릅니다.
3. 파일럿 근거가 있어야 판단할 수 있는 값은 지금 동작을 유지하고 파일럿에서 다시 봅니다.

## 결과

- D-01~D-11을 작업 단위별로 구현합니다. 구현 내용은 해당 ADR이 아니라 이 문서와 커밋에 남기고, 각 ADR에는 이 문서를 가리키는 표시만 답니다.
- 파일럿 근거로 다시 볼 값은 위 표에 남습니다. 뒤집을 때는 새 ADR로 합니다.
- 짧은 영상은 [실행 계획 §4.4](../planning/DELIVERY_PLAN.md)의 E-15로 남깁니다.

## 구현 중 달라진 점

- **D-01 보완**: 이름만 가리면 부족했습니다. 사용자 id는 과제 멤버 목록·실명 방과 같은 값이라, 같은 사람과 과제를 함께 하는 방장이 맞춰 보면 표시명이 누구인지 알 수 있었습니다. 표시명·익명 방의 멤버 목록은 다른 사람의 id를 방별 키(`rm_…`, `community/space-member-refs.ts`)로 내보내고, 관리 경로도 그 키와 본인 id만 받습니다. 다른 사람의 실제 id는 404입니다. [ADR 0026 부록](0026-study-records.md)의 익명 스터디 기록과 같은 방식입니다.
- **D-11은 완전한 일치가 아닙니다**: SQL은 기능 플래그를 볼 수 없어 `institutions` 플래그와 관련한 차이 두 가지가 남습니다. 기관 운영진에게는 플래그와 무관하게 카드가 없고(테스트로 고정), 기수 방 멤버에게는 플래그가 꺼져 있어도 카드가 나갑니다(테스트 없음). 플래그가 꺼져 있으면 기수 방을 새로 만들 수 없어 지금 영향은 없습니다. 플래그를 켠 뒤 끄는 운영이 생기면 함수에 플래그 인자를 더합니다.
