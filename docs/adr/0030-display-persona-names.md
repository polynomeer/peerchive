# 0030. 표시명 방식 = 표시명 페르소나: 쓰기 전에 active 표시명 페르소나 요구 + 글에 고정한 persona_id의 이름만 표시 + 페르소나 없는 예전 글은 중립 표시 + 계정 이름으로 돌아가는 길 제거

- 상태: 채택
- 날짜: 2026-10-28
- 변경: D-01: 표시명 방의 멤버 목록도 계정 이름·실명 handle 대신 방별 이름·표시명 페르소나 이름을 냅니다 ([ADR 0060](0060-open-question-decisions.md)).

## 맥락

커뮤니티 이름 표시 방식(ADR 0020, C-03)은 anonymous·display·real이고, S-01 전에는 페르소나가 없어 `display` 글의 작성자를 **계정 표시 이름(`users.display_name`)** 으로 보여 줬습니다. 그런데 계정 표시 이름은 실명 페르소나의 공개 프로필(`/u/<handle>`, ADR 0028)에 보이는 이름이기도 합니다. S-01(ADR 0028)이 자기 이름·handle을 가진 표시명 페르소나(`personas.kind = 'display'`)를 만들었고, S-02(ADR 0029 §4)가 `community_posts`·`community_comments.persona_id`를 작성 시점에 고정했지만(표시명 방식 → 표시명 페르소나, 없으면 NULL) **작성자 표시는 그대로 두었습니다**. 그래서 지금 표시명 글은 계정 이름으로 보이고, 읽는 사람이 그 이름으로 실명 프로필을 찾을 수 있습니다. ADR 0029의 후속 항목("표시명 글의 작성자 표시: 투영을 켜기 전에 표시명 페르소나 이름으로 바꿔야 함")이 이 결정입니다. S-05에서 표시명 페르소나 투영(활동 목록·피드)을 열면 "계정 이름으로 보이는 글"과 "표시명 프로필의 활동"을 맞춰 두 페르소나를 잇게 되므로 그 전에 고쳐야 합니다.

관련 설계: PROOFU_EVOLUTION_PLAN §4.4(표시명은 실명과 별도의 정체성이고 연결은 사용자가 켤 때만 보임), SYSTEM_DESIGN §6.7.1(Persona, IdentityLink, "글의 페르소나 귀속" — real·display 글은 작성 시점 `persona_id` 고정), §6.7·§8.1(커뮤니티 응답에는 사람 id·handle·프로필 링크가 없음, 방장·모더레이터용 API도 같은 공개 DTO), ADR 0020(작성 시점 고정, 실명 방식은 실명 입력 전 403 `real_name_required`), ADR 0022(작성자 DTO), ADR 0025(막힘 Q&A 복사본의 이름), ADR 0028·0029.

## 결정

### 1. 쓰기: 표시명 방식에는 active 표시명 페르소나가 필요

- 글·댓글을 쓰는 트랜잭션(공간 FOR SHARE 잠금 안, `decideNameMode`)에서 방식이 `display`로 정해지면 **그 사람의 `kind = display`·`status = active` 페르소나**를 찾습니다. 없으면 **403 `display_persona_required` + `requirement: 'display_persona'`** 입니다 — 실명 방식의 `real_name_required`(`requirement: 'real_name'`)와 같은 모양이고, 아무것도 쓰이지 않습니다(분석·스레드 번호·rate limit 모두 그 뒤).
- 찾은 페르소나 id를 그대로 `persona_id`에 고정합니다(S-02의 "없으면 NULL"은 이제 새 표시명 글에 생기지 않음). 실명 페르소나·계정 이름으로 대신하지 않습니다. 실명 방식은 그대로(실명 요구, 실명 페르소나 있으면 고정·없으면 NULL), 익명은 조회하지 않고 NULL입니다.
- 공식 페이지는 익명 기본이라 **표시명을 고른 글·댓글만** 막힙니다. 비활성(`deactivated`) 표시명 페르소나로는 쓰지 못합니다(지금은 비활성화 경로가 없지만 상태 값은 있음).
- **글쓰기 미리 보기**: `CommunityComposerDto.displayPersonaRequired` = 고를 수 있는 방식에 `display`가 있는데(표시명 방, 공식 페이지의 표시명 선택) active 표시명 페르소나가 없음. 화면(게시판 글쓰기·글 상세 댓글)은 표시명 방이면 바로, 공식 페이지면 "표시명"을 골랐을 때 `/settings/personas`(표시명 프로필 만들기) 링크와 "계정 이름은 표시명으로 쓰지 않습니다" 안내를 보입니다. 답글 등 다른 곳에서 403을 받으면 같은 문구의 오류를 보입니다.
- 표시명 프로필을 만드는 데에는 실명 프로필이 먼저 있어야 합니다(ADR 0028, 409 `real_persona_required`). 온보딩을 마친 사용자는 실명 프로필이 있으므로 추가 단계는 "표시명 프로필 만들기" 하나입니다.

### 2. 표시: 글에 고정한 표시명 페르소나의 **지금** 이름만, 링크 없음

- `resolveAuthorDisplay`의 재료(`AuthorProfileBits`)에서 계정 표시 이름(`displayName`)을 **없애고** `displayPersonaName`(그 글에 고정한 표시명 페르소나의 이름, 없으면 null)으로 바꿨습니다. 타입에 계정 이름이 없으므로 표시명 글이 계정 이름으로 돌아갈 코드 경로 자체가 없습니다. 커뮤니티 모듈의 작성자 조회도 `users.display_name`을 읽지 않습니다.
- 이름은 글마다 `persona_id`로 찾고, **`kind = 'display'` 행만** 읽습니다(`displayPersonaNames`). DB 트리거(ADR 0029)가 표시명 글에 실명 페르소나를 붙이지 못하게 막지만, 읽는 쪽도 종류를 걸어 어떤 경우에도 실명 페르소나 이름이 나오지 않게 했습니다.
- **이름을 바꾸면 지금 이름**: 새 열을 두지 않고 읽는 시점의 `personas.display_name`을 씁니다. 같은 표시명 정체성의 이름이 바뀐 것이고(handle처럼 같은 사람), ADR 0020의 "고정하는 것은 방식, 이름은 읽을 때의 값"과 같은 원칙입니다. 글마다 이름을 복사하면 탈퇴·정정 때 지울 곳이 늘어납니다. 작성 시점 고정 대상은 여전히 방식과 페르소나(정체성)입니다.
- **handle·프로필 링크는 싣지 않습니다**: 설계(§6.7.1·§6.7)는 표시명 글을 표시명 프로필에 링크하라고 하지 않고, 커뮤니티 DTO 계약은 "사람 id·handle·프로필 링크 없음"(방장·운영자 포함)입니다. 표시명 글이 표시명 정체성의 것임은 의도한 일이지만, 링크는 S-05에서 활동 목록·공개 범위·차단과 함께 정할 일이라 지금은 이름만 보입니다.
- **비활성·숨김**: 페르소나가 비활성이거나 표시명 프로필이 운영 조치로 숨겨져도(`profiles.hidden_at`) 이미 쓴 글의 이름은 그대로 보입니다(링크가 없으므로 숨긴 프로필로 가는 길이 없음). 이름까지 지우면 "이 사람의 프로필이 숨겨졌다"는 신호가 되고, 글 자체의 가리기는 기존 운영 조치(ADR 0022·0023)가 합니다. 탈퇴 정리는 기존대로 `persona_id`를 비우고 "탈퇴한 사용자"로 보입니다(withdrawn이 먼저).
- 같은 표시를 운영자 신고 화면의 작성자 이름(`operatorCommunityItem.authorLabel`)도 씁니다.

### 3. `persona_id`가 없는 예전 표시명 글: 중립 표시 "표시명 없음"

- S-01 이전 글, 그리고 S-02~이 결정 사이에 표시명 페르소나 없이 쓴 글은 `persona_id`가 NULL입니다. 이 글들은 **계정 이름 대신 "표시명 없음"** 으로 보입니다(`DISPLAY_PERSONA_MISSING_LABEL`, `kind: 'display'`, 본인에게는 `mine: true`). 실명 페르소나로 대신하지 않습니다.
- 이유: 계정 이름을 계속 보이면, 같은 사람이 나중에 표시명 페르소나를 만들어 **같은 방에** 쓸 때 한 화면에 "김지민(예전 글)"과 "밤의개발자(새 글)"가 함께 남아 글 흐름·문체로 두 정체성이 이어질 수 있습니다. 중립 표시는 그 새 연결을 앞으로 만들지 않습니다. 이미 계정 이름으로 본 사람에게서 되돌릴 수는 없지만(아래 결과), 바꾼다고 더 드러나는 것은 없습니다.
- 대가: 예전 표시명 글의 작성자 이름 정보가 사라집니다. 이 시점의 예전 표시명 글은 개발·시범 데이터뿐이라 받아들입니다. 기존 행은 고치지 않습니다(`persona_id`를 소급해 붙이면 S-02가 막은 "나중에 만든 페르소나에 예전 글 붙이기"가 됨, migration 없음).

### 4. 막힘 Q&A 복사본의 "표시명"(ADR 0025)

- 옮기기 요청·동의에서 고르는 복사본 이름 `display`도 같은 문제(계정 이름 복사)여서 같이 바꿨습니다. `display`는 **active 표시명 페르소나의 이름**이고, 없으면 **422 `displayMode: display_persona_required`**(실명의 `real_name_required`와 같은 자리, 이전의 `display_name_missing`을 대신함). 동의 행의 `display_label`은 기존대로 그 순간의 문자열을 복사해 둡니다(공개 복사본이 원 글·사람과 이어지지 않게 하는 ADR 0025의 구조 그대로).
- 선택지 응답(`ArchiveOptionsDto.displayName`·`ArchiveTransferDto.displayOptions.displayName`)도 표시명 페르소나 이름이고 없으면 null이며, 화면은 표시명 선택지 대신 `/settings/personas` 안내를 보입니다. 선배 노트로 옮길 때의 표시명은 노트 화면에서 직접 적는 별도 값(ADR 0013)이라 바꾸지 않았습니다.

### 5. 다른 표시명 사용처 점검

- 모집·지원(C-07): 지원자 이름은 모집자에게만 보이는 계정 이름이고 이름 표시 방식과 무관합니다(모집 글은 커뮤니티 글이 아님). 모집으로 만드는 스터디 방의 방식(`roomNameMode`)은 공간 설정일 뿐입니다. 스터디 기록(C-08)은 방 방식만 과제 행으로 옮기고 이름을 쓰지 않습니다. 스레드 번호는 익명 전용입니다. 그래서 이번 범위는 글·댓글(쓰기·표시·운영자 화면)과 막힘 Q&A 복사본 이름입니다.
- 경계: 커뮤니티 모듈이 `personas`를 읽는 것은 허용 방향입니다(ADR 0029: social은 커뮤니티를 읽지 않음). 도우미(`activeDisplayPersona`·`displayPersonaNames`·`displayPersonaRequiredError`)는 `server/modules/community/name-modes.ts`에 두었고 social 쪽 파일은 바꾸지 않았습니다.

## 결과

- 새 표시명 글·댓글은 언제나 표시명 페르소나에 고정되고 그 이름으로만 보입니다. 커뮤니티 응답(글·목록·댓글·운영자 화면)에 계정 표시 이름·실명 handle·표시명 handle이 없음을 통합 테스트와 E2E가 확인합니다. S-05의 표시명 투영은 이 상태에서 켤 수 있습니다(예전 NULL 글은 투영 대상도 아님, ADR 0029).
- DB·migration 변경 없음(작성 시점 `persona_id`·트리거는 0027 그대로).
- 한계·후속:
  - 이미 계정 이름으로 표시명 글을 본 사람·저장한 사본에서는 되돌릴 수 없습니다.
  - **방 멤버 목록**(`GET …/members`, owner·admin만)은 여전히 계정 이름과 실명 handle을 보여 줍니다. 멤버가 적은 표시명 방에서는 방장·admin이 표시명 작성자를 멤버 중 한 명으로 좁힐 수 있습니다. 멤버 목록을 방 방식에 맞춘 이름으로 보일지는 S-05(또는 P2 RoomProfile)에서 정합니다.
  - 페르소나 비활성화 경로가 생기면(현재 없음) 그 화면에 "이전 표시명 글은 이름이 그대로 보입니다"를 안내해야 합니다.

## 대안

- **예전 NULL 글은 계속 계정 이름**: 정보는 남지만 §3의 새 연결(같은 방의 예전·새 글)이 계속 생깁니다.
- **표시명 페르소나가 없으면 계정 이름으로 쓰게 두기**(지금까지 동작): 별도 단계가 없어 편하지만, 표시명 방이 사실상 실명 프로필 이름 방이 됩니다.
- **페르소나가 없으면 자동으로 만들기**: handle·표시명을 사용자가 고르지 않은 정체성이 생기고, 계정 이름을 기본값으로 쓰면 같은 문제가 됩니다.
- **글마다 작성 시점 이름 복사**: 이름을 바꿔도 예전 글은 예전 이름이지만, 같은 정체성의 이름 정정이 따라가지 않고 탈퇴·정정 때 지울 열이 늘어납니다(ADR 0020과 같은 이유로 고르지 않음).
- **표시명 글에 표시명 프로필 링크**: 의도된 연결이지만 설계에 없고 공개 범위·차단 규칙(S-05) 전에는 DTO 계약을 바꾸지 않습니다.
