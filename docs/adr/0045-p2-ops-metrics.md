# 0045. P2 운영·계측: 동문 방 항목 하나를 가리키는 신고·숨김(`room_item` + 종류) + 소속·기수 사칭 사유 + 인증 수단별 처리 큐(수료증 받은 시각 → 결정 시각) + 시 단위·익명 키 없는 §6.2 P2 이벤트와 5 미만 가림 지표

- 상태: 채택
- 날짜: 2026-11-02

## 맥락

A-07은 DELIVERY_PLAN §4.3 P2 백로그의 마지막 항목입니다: "명부·일정·토픽 신고 사유, 기관 인증 수단별 처리 큐(수료증 확인 시간 기록), §6.2 P2 이벤트". §7 GA 게이트는 A-03 명부·A-05 임계값 회귀 테스트와 "수료증 파일 삭제 절차와 기관 운영진 권한 범위 검토"를 요구하고, §6.2는 P2 지표(졸업생 → 선배 노트 공급(핵심)·토픽 → 선배 노트 전환·동문 방 활성·명부 동의율·소속 표시 상향 비율·기관 인증·기관 확장 공급)와 분석 이벤트 `alumni_room_created`·`event_created`·`rsvp_submitted`·`directory_consent_changed`·`topic_post_created`(label_scope_applied·broadened)·`affiliation_verified`(method)·`completion_retro_published`를 적었습니다. 기관 인증 지표의 판단 초안은 "수료증 확인 처리 중앙값 3일 이내, 사칭 확정 시 승인 경로 점검"입니다. 관련 결정:

- ADR 0015(신고·조치·이의제기: 지금 볼 수 있는 것만 신고, 대상 단위 처리, 감사는 id·종류만, 조치마다 이의제기 한 번), 0016(분석: 허용 목록 props·HMAC 사용자 키·수집 거부·지표 5 미만 가림), 0023(작성자 확인은 운영자 사유 기록 경로만, 방 운영진은 작성자를 모름), 0027(키 없는 이벤트 = `actor_hash` null, 운영 기록은 개수로만, 모든 칸 5 미만 가림, 처리 기한 배지), 0036(신고·조치 행에 주인 사용자 id를 두지 않음, 페르소나 이벤트는 사용자 키 + 시 단위 시각).
- ADR 0037(수료증 결정 시각 `decided_at`, 결정 뒤 파일 삭제), 0038~0041(동문회·OB 방·방별 프로필·일정·투표·앨범·명부·라운지), 0042(토픽·소속 표시 익명·작성 시점 고정 표시), 0043(수료 회고 — 이미 신고 대상), 0044(기관 운영진은 모더레이터 범위, 작성자 확인 없음).
- 남은 문제: 방별 프로필·일정·투표·앨범 사진·명부 항목은 신고 대상이 아니었습니다(ADR 0038~0040). 명부 항목은 응답에 id가 없었습니다(ADR 0040).

## 결정

### 1. 신고 대상 `room_item`: 종류 + 항목 id 하나 (migration `0042_p2_ops_metrics`)

| 종류(`room_item_kind`) | 신고할 수 있는 사람(지금 볼 수 있는 것) | 당사자 | 숨김 효과 |
|---|---|---|---|
| `directory_entry` 명부 항목 | 그 방 active 멤버, 익명이 아닌 방, 주인이 active 멤버 | 그 사람 | 다른 멤버의 명부에서 빠짐, 본인에게 `hidden: true` |
| `room_profile` 방별 프로필 | 같음 | 그 사람 | 목록·글 작성자 표시·응답자·명부 이름에서 없는 것처럼(`방별 이름 없음`, 배지·기수 없음), 본인에게 `hidden: true` |
| `event` 일정 | 그 방 active 멤버 | 만든 사람 | 목록에서 빠지고 고치기·취소·응답·응답자 경로 404(방장·운영진 포함) |
| `poll` 투표 | 그 방 active 멤버 | 만든 사람 | 목록에서 빠지고 투표·마감 404 |
| `album_photo` 앨범 사진 | 그 방 active 멤버, 검사 통과 사진 | 올린 사람 | 목록(올린 사람 포함)·서명 URL 404 |

- 신고 값 `{spaceSlug, kind, itemId}`. 판정은 각 화면과 같은 `loadAlumniRoom`(alumni 플래그 → 읽을 수 있는 공간 → active 멤버 → alumni 방, 아니면 404)과 항목 행(그 방·숨기지 않음)입니다. 형식 오류 422.
- `reports`·`moderation_actions`에 `room_item_kind`(새 enum)·`room_item_id`를 더했고 **외래 키가 없습니다**(명부 철회·나가기·탈퇴 정리가 행을 지워도 신고·조치 기록은 남고 운영 화면은 "찾을 수 없음"). **주인 사용자 id는 두지 않습니다**(ADR 0036과 같은 이유). 대상 키 `room_item:<kind>:<id>`.
- 명부 항목은 기본 키가 (방, 사람)이라 가리킬 값이 없어 `directory_entries.id`(무작위 uuid, 유일 색인)를 더하고 DTO에 실었습니다. ADR 0040의 "항목 id 없음"을 바꾼 것이며, 이 id는 동의마다 새로 생기는 무작위 값이라 사람 id가 아니고 다른 방 항목과 이어지지 않습니다.
- 숨김은 다섯 표 모두 `hidden_at` 한 열입니다(지우지 않음, 되돌리면 null). 조치 `hide_room_item` 하나로 다섯 종류를 처리합니다(enum `ADD VALUE`와 분기를 줄임).
- 이름표: `종류 · 방 이름`(예: `일정 · 12기 동문회`). 당사자 화면 주소는 종류별 방 화면(`/community/directory|gatherings|room-profiles/:slug`).
- 운영자 상세(`OperatorRoomItemDto`): 방 이름·지금 이름 표시 방식·숨김 여부·항목 값. 명부·방별 프로필은 **방 멤버에게 보이는 이름**(실명 방은 실명, 표시명 방은 방별 이름)만, 일정·투표·사진은 **만든·올린 사람 없음**(멤버 화면에도 없음). 사진은 운영자에게만 맞는 5분 서명 URL(`/api/v1/operator/community/room-items/album-photos/:id/file`, 멤버 서명과 접두어가 달라 서로 쓸 수 없음, 숨긴 사진도 보임 — 이의제기 판단용). 계정 id·계정 이름·표시명 페르소나는 싣지 않습니다(테스트).
- 방장·운영진·기관 운영진·방 모더레이터는 이 신고를 보지 않습니다(운영자 대기열뿐). 방 운영진의 기존 가리기(`space_hide`)는 글·댓글만입니다.
- 숨긴 명부 항목도 **철회할 수 있습니다**(철회권이 우선, ADR 0040). 그 뒤 다시 동의하면 새 행(새 id)이라 숨김이 이어지지 않습니다 — 다시 신고로 다룹니다. 숨긴 사진도 올린 사람·방장·운영진이 지울 수 있습니다(지우면 되돌릴 것이 없음). 소셜 링크처럼 숨긴 동안 지우기를 막지 않은 이유는 둘 다 본인 자료의 삭제권이기 때문입니다.
- C-05 경계: 판정·효과는 커뮤니티 모듈 `community/room-item-reports.ts`에 두고 `community/reporting.ts`가 다시 내보냅니다. moderation 쪽은 `targets`·`actions`·`operator`만 import하고, `notices`·`reports`는 `targets`를 거쳐 받습니다(경계 테스트의 허용 목록 그대로).

### 2. 소속·기수 사칭 사유 `affiliation_impersonation`

- 설계 문서에 토픽 전용 사유 이름은 없지만, §6.2 기관 인증 지표의 "사칭으로 판정된 인증 수"와 §9.2 위험 "가짜 기수·기관 인증 사칭"을 셀 자리가 필요해 사유 하나를 더했습니다: **토픽 글의 소속 표시, 명부·방별 프로필의 기수, 수료 회고의 기관이 사실과 다르게 보이게 함**.
- 고를 수 있는 대상: 커뮤니티 글·댓글(토픽의 소속 표시 익명 포함)·수료 회고·방 항목 중 명부 항목·방별 프로필(@peerchive/domain `reasonApplicable(target, reason, roomItemKind)`, 아니면 422 `reason: not_applicable`, DB check `reports_affiliation_impersonation_check` — `::text` 비교). 일정·투표·사진·페르소나에는 없습니다(표시명 사칭 `impersonation`은 그대로 프로필에만).
- 처리: 운영자가 신고 상세에서 판단하고, 필요하면 기존 작성자 확인(소속 표시 익명 글이면 표시에 쓴 소속 id도 함께, ADR 0042)으로 그 소속을 찾아 운영자 소속 취소(RUNBOOK §4.1·§4.6)를 합니다. 신고 상세 자체에는 작성자가 없습니다(테스트: 소속 표시 익명 토픽 글 신고의 상세 JSON에 계정 id·이름·페르소나 0건).

### 3. 인증 수단별 처리 큐

`GET /api/v1/operator/institutions/verification-queue`(운영자만, `institutions` 플래그 꺼짐 404, 화면 `/operator/verification-queue`):

| 수단 | 큐 | 보이는 것 |
|---|---|---|
| 초대 코드 | 없음(쓰는 순간 인증) | 최근 7일 사용 수(5 미만 null), 지금 쓸 수 있는 코드 수 |
| 기수 승인 | 같은 기수 멤버 2명의 승인 대기 — **운영자가 처리하지 않으므로 기한 없음** | 오래된 순: 기관·기수, 요청 시각·나이, 받은 승인 수/필요 수, 만료 시각(30일). 요청한 사람·승인한 사람 없음 |
| 수료증 확인 | 운영자 대기(파일을 받았고 결정 전, 소속 pending) | 오래된 순: 기관·기수, **받은 시각(uploaded_at)**·나이·검사 상태, 건별 기한 상태(ok·곧 기한(75%)·기한 넘김) + 최근 30일 결정의 처리 시간 요약 |

- **처리 시간 = 받은 시각(uploaded_at) → 결정 시각(decided_at)**. 요청 시각(created_at)이 아니라 받은 시각에서 재는 것은 운영자가 볼 수 있는 시점부터의 운영 부담을 재기 위해서입니다(사용자가 파일을 늦게 올린 시간은 빼야 운영 지표가 됨). `decided_at`은 I-01이 이미 남기므로 새 열이 없습니다.
- 건별 기한 `PEERCHIVE_CERTIFICATE_SLA_HOURS`(기본 **72시간**), 중앙값 목표 72시간(§6.2 "처리 중앙값 3일 이내", 설계 값이라 환경 변수로 바꾸지 않음). 요약은 결정 수·중앙값·p90(가장 가까운 순위)·기한 안 비율이고 **표본 5 미만이면 중앙값·p90 null**(@peerchive/domain `summarizeDecisionTimes`).
- 이 설계 값이 있으므로 RUNBOOK §4.6의 `<시간>` 자리를 "건별 72시간·중앙값 3일"로 채웠습니다.

### 4. §6.2 P2 이벤트

| 이벤트 | 어디서 | props | 사용자 키 |
|---|---|---|---|
| `alumni_room_created` | 동문회·OB 방 만들기, 기수 방 만들기(I-02) | `mode`, `cohortRoom` | 있음 |
| `event_created` | 일정 만들기 | `recurrence` | **익명 방이면 없음** |
| `rsvp_submitted` | 회차 응답(처음·다른 응답으로 바꿀 때만, 지우기·같은 응답은 세지 않음) | `response`, `changed` | **익명 방이면 없음** |
| `directory_consent_changed` | 처음 동의·본인 철회(항목 바꾸기는 세지 않음) | `consented`, `filled`(채운 항목 수) | 있음(명부는 익명 방에 없음) |
| `topic_post_created` | 토픽 글 | `labelScope`(적용 범위), `broadened` | **익명·소속 표시 익명이면 없음** |
| `completion_retro_published` | 수료 회고 게시 | `displayMode`, `labelScope`, `broadened` | **익명 회고면 없음** |
| `affiliation_verified`(기존) | 메일·초대 코드·기수 승인·수료증 확인 | `standing` + **`method`** | 있음 |

- 새 6개는 `emitP2Analytics`로 **시 단위 시각**(ADR 0036의 `socialEventTime`)·프로젝트 키 없음. 방·글·기관·기수·페르소나 id와 이름·명부 값은 허용 목록에 자리가 없습니다(도메인 테스트: 키 이름에 id·name·space·institution·handle 없음, 넣으면 이벤트 전체 거부). 수집 거부·탈퇴 정리·pepper 교체는 ADR 0016 그대로입니다(테스트: 거부한 사람의 응답은 0건).
- 익명 방의 일정·응답에 키를 붙이지 않은 이유: 익명 방은 응답자 이름을 수로만 보여 주므로, 응답 이벤트의 사용자 키가 "이 사람이 그 익명 방에 있다"를 분석 표에 남기는 유일한 기록이 됩니다. §6.2의 "0~1단계 글 이벤트에는 사용자 키 없음"을 같은 정도로 넓혔습니다.
- `affiliation_verified`는 C-01부터 있던 이벤트라 시각 처리를 바꾸지 않고 `method`만 더했습니다(기관 id·기수는 넣지 않음).

### 5. P2 지표

`GET /api/v1/operator/metrics/community/p2?from=&to=`(운영자만, 화면 `/operator/metrics`의 "졸업생·토픽·기관" 칸). 커뮤니티 테이블을 세므로 C-05 경계에 따라 커뮤니티 집계 모듈(`community/ops-metrics.ts`)과 `/operator/metrics/community/*` 아래에 둡니다(`GET /operator/metrics`의 `ops` 모듈은 커뮤니티 테이블을 읽을 수 없음). **영역 플래그가 꺼진 칸은 null**(화면에서 숨김), **모든 칸 5 미만 null**, 비율은 분자·분모 중 하나라도 가려지면 null(@peerchive/domain `computeP2Metrics`).

| 지표(§6.2) | 정의 |
|---|---|
| 졸업생 → 선배 노트 공급(핵심) | 기간 안에 동문 방 활동(방 만들기·일정·응답·명부, 키 있는 이벤트)을 한 사람 중 같은 기간 선배 노트·수료 회고를 게시한 사람(같은 기간 근사, 토픽 참여는 키가 없어 빠짐) + 게시 합계 |
| 토픽 → 선배 노트 전환 | 기간 안 토픽 답변(댓글) 중 선배 노트로 옮겨진(이동 완료) 것 |
| 동문 방 활성 | 보관되지 않은 동문 방 중 기간 안에 일정을 만들었거나 공지 글이 있던 방(§6.2 "월 1회"의 기간 근사) |
| 일정당 참석 응답률 | 기간에 걸친 숨기지 않은 일정의 (일정, 응답한 active 멤버) 수 / 그 방 지금 active 멤버 수 합 |
| 명부 동의율 | 지금 명부 행 / 익명이 아닌 동문 방의 active 멤버(관찰 지표) |
| 소속 표시 상향 | 토픽 글 중 넓혀진 비율과 적용 범위별 수 |
| 기관 인증 | 수단별 인증 수(대학 메일 제외), 수료증 처리 시간(3절 요약), 사칭 판정(운영자 소속 취소 수, 소속·기수 사칭 신고·확정 수) |
| 그 밖 | 방 항목 종류별 신고 수·숨김 확정 수, 수료 회고 게시 수 |
| 기관 확장 공급 | 기수 방과 과제·공개 사례를 잇는 기록이 없어 **재지 않음**(null, 화면에 표시) |

## 결과

- 동문 방의 다섯 항목을 그 항목 하나만 신고·숨기고 이의제기로 되돌립니다. 신고·조치 기록과 운영자 화면 어디에도 주인 사용자 id가 없고, 운영자는 방 멤버가 보는 것만 봅니다.
- 소속·기수 사칭 사유로 §6.2 "사칭으로 판정된 인증"을 셀 수 있습니다.
- 수료증 처리 시간이 받은 시각 → 결정 시각으로 큐·지표에 나오고, 5건 미만이면 가립니다. 기수 승인은 운영자 큐가 아니라 관찰 목록입니다.
- §6.2 P2 이벤트 6개와 `affiliation_verified.method`가 생겼고, 익명 내용의 이벤트에는 사용자 키가 없습니다.
- 마이그레이션은 enum `ADD VALUE` 4종(분석 이벤트·조치·사유·대상)을 더하고, 그 값을 쓰는 check는 모두 `::text`로 비교합니다. 빈 DB에서 처음부터 migrate되는 것을 확인했습니다.
- 테스트: 도메인 `p2-ops.test.ts`(대상·사유 규칙, 이벤트 허용 목록, 기한·백분위·가림, 지표 계산·플래그), `analytics.test.ts`(이벤트 52개), web `p2-ops.integration.test.ts`(종류별 신고 → 대기열 → 숨김 → 이의제기 되돌림, 운영자 상세에 주인 없음, 숨긴 명부·프로필의 본인 표시와 이름 대체, 철회 뒤 "찾을 수 없음", 사칭 사유 대상·DB check, 소속 표시 익명 토픽 글 작성자 비노출, 처리 큐 묶음·나이·기한·처리 시간 가림, 이벤트 키·시각·수집 거부·id 없음, 지표 플래그·가림, 숨긴 일정·투표·사진의 상세 경로 404).
- 한계·후속:
  - 숨긴 명부 항목을 철회한 뒤 다시 동의하면 숨김이 이어지지 않습니다(새 id). 반복되면 방 운영진의 내보내기·운영자 이용 제한으로 다룹니다.
  - 공지 읽음·투표 표·참석 응답은 개인 행동이라 신고 대상이 아닙니다(내용이 없음). 공지 글은 기존 커뮤니티 글 신고입니다.
  - 일정당 응답률·동문 방 활성은 기간 근사이고, 기관 확장 공급은 잴 수 없습니다.
  - 기수 승인 큐는 운영자가 처리하지 않으므로 기한·지표를 두지 않았습니다. 승인 연쇄 사칭은 소속 취소 수와 사칭 신고로만 봅니다.
  - 운영자 감사 조회에서 동문 방 항목을 만든 사람의 감사 행(`community.room_event_create` 등, metadata에 항목 id)으로 주인을 찾을 수 있습니다. 운영자만 보는 경로이고 일정·투표·사진은 익명 내용이 아니라 ADR 0036처럼 행위자를 비우지 않았습니다.

## 대안

- **종류마다 새 대상 enum(`directory_entry`·`room_event`·…)과 조치 다섯 개**: 이름은 분명하지만 enum `ADD VALUE` 열 개, 열 열 개, check·분기 다섯 배가 늘고 얻는 규칙은 같습니다. 종류 enum 하나 + 대상 하나로 묶었습니다.
- **신고·조치 행에 주인 사용자 id 저장**: 당사자 찾기가 쉽지만 운영 기록이 사람 단위 연결표가 됩니다(ADR 0036과 같은 이유). 당사자는 그때 항목 행으로 찾습니다.
- **방 운영진(방장·운영진·기관 운영진)이 방 항목 신고를 처리**: 빠르지만 신고자·신고 내용이 방 운영진에게 보이고, 기관 운영진이 기수 방 신고로 사람을 모을 수 있습니다(ADR 0044 §7). 운영자 처리로 두고 방 운영진은 기존 도구(일정·투표 취소, 사진 지우기)를 씁니다.
- **수료증 처리 시간을 요청 시각부터**: 단순하지만 사용자가 파일을 늦게 올린 시간이 운영 지표에 섞입니다.
- **P2 칸을 `GET /operator/metrics`에 넣기**: 한 번에 보이지만 `ops` 모듈이 커뮤니티 테이블을 읽게 되어 C-05 경계를 깹니다. 같은 화면에서 별도 경로로 불러옵니다.
- **익명 방의 일정·응답 이벤트에도 사용자 키**: 사람 단위 활성 지표가 정확해지지만 익명 방 참여가 분석 표에 사람 단위로 남습니다.
