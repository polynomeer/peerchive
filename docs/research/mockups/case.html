셸 구현 과제

운영체제 · 2026-1 · 2인 · 약 25시간

🌐 전체 공개 요약·마일스톤·선택한 로그·선택한 산출물 버전·기여가 보입니다.

작성: 김지민, 박서연(표시명) · 팀원 공개 동의 2/2

보기 방식 (같은 공개 버전, 순서만 다름)

대안·실패·막힘·참고 자료를 먼저 보여 줍니다.

요약

문제: 파이프·리다이렉션·백그라운드 실행을 지원하는 작은 셸을 C로 만드는 과제였습니다.

결과: 파이프 3단 연결과 입출력 리다이렉션은 직접 만든 테스트 42개를 통과했습니다. 잡 컨트롤(fg/bg)은 범위에서 뺐습니다.

빌드 로그 — 주요 전환점

시간순 전체가 아니라 결정·막힘 해결·검증 중심으로 묶었습니다. 날짜는 작성자가 기입한 수행일이며, 서버 저장 시각은 별도로 표시합니다.

전환점 1 · 파서와 실행부를 나누다 (마일스톤 1 → 2)

  • 🔨 진행4/05 · 김지민

    공백 기준으로만 자르는 첫 파서 완성. 따옴표 들어가면 바로 깨짐.

  • ⚖️ 결정4/08 · 김지민 · 저장 4/08 21:14

    파서를 상태 기계로 다시 짜고 실행부와 분리하기로 함.

    선택지
    ① 기존 파서에 예외 처리 추가 ② 상태 기계 파서로 재작성
    판단 기준
    테스트 가능성, 2인 분업 가능 여부, 남은 기간 5주
    선택
    ② 재작성. 파서 출력 구조를 먼저 합의해 실행부를 박서연이 병렬로 진행
    지나고 보니
    재작성에 3일 들었지만 이후 파이프·리다이렉션 추가 때 파서를 거의 건드리지 않았음

전환점 2 · 파이프가 끝나지 않는 문제 (마일스톤 3)

  • 🧱 막힘4/28 · 박서연

    두 번째 명령이 입력 끝을 받지 못하고 계속 대기함.

    증상
    cat f | wc 실행 후 프롬프트가 돌아오지 않음
    맥락 키워드
    pipe, dup2, close, EOF
    오류 메시지
    없음 (무한 대기)
    시도한 것
    버퍼 크기 변경 → 변화 없음 · 자식에서 출력 플러시 → 변화 없음
    걸린 시간
    반나절 이상
  • 💡 해결4/29 · 박서연 · ↳ 위 막힘과 연결됨

    부모 프로세스가 파이프 쓰기 끝을 열어 둔 채라 EOF가 오지 않았음. 각 프로세스에서 쓰지 않는 끝을 모두 닫는 원칙을 정함. (접근 설명만 공개, 코드 비공개)

전환점 3 · 좀비 프로세스 (마일스톤 3 → 4)

  • 🧱 막힘5/12 · 김지민

    백그라운드 실행 후 ps에 <defunct> 프로세스가 쌓임.

    증상
    백그라운드 명령 10번 실행하면 좀비 10개
    맥락 키워드
    wait, waitpid, SIGCHLD, 백그라운드
    오류 메시지
    없음
    시도한 것
    명령마다 wait() 호출 → 백그라운드가 사라짐(블로킹) · gdb로 자식 추적
    걸린 시간
    하루 이상
  • 💡 해결5/13 · 김지민 · ↳ 위 막힘과 연결됨

    자식 종료 신호를 받을 때 기다리지 않는 방식으로 회수하도록 바꿈. 시그널 핸들러 안에서 할 수 있는 일이 제한된다는 점을 교재 10장에서 확인.

  • 🧱 막힘5/20 · 김지민 · 미해결

    Ctrl+C가 포그라운드 자식뿐 아니라 셸에도 전달됨. 프로세스 그룹 문제로 추정했지만 기한 내 해결하지 못함.

전환점 4 · 범위를 줄이고 검증하다 (마일스톤 4)

  • ⚖️ 결정5/22 · 김지민, 박서연

    잡 컨트롤(fg/bg)을 범위에서 빼고 테스트에 시간을 쓰기로 함.

    선택지
    ① 잡 컨트롤까지 구현 ② 기존 기능 안정화와 테스트
    판단 기준
    남은 2주, 평가 기준 공지의 필수/선택 구분, 미해결 시그널 문제
    선택
    ② 안정화. 보고서에 미구현 사유를 명시
    지나고 보니
    필수 기능 감점이 없었고, 미구현 이유를 설명할 수 있어 발표 질의가 수월했음
  • ✅ 검증6/03 · 김지민
    대상
    파서, 파이프, 리다이렉션, 백그라운드 실행
    조건
    직접 만든 테스트 스크립트 42개, 과제 서버(리눅스)와 macOS 양쪽
    결과
    리눅스 42/42 통과 · macOS 40/42 (출력 형식 차이 2건)
    남은 불확실성
    입력이 매우 긴 경우, 시그널 처리 전반은 테스트하지 않음
  • ✅ 검증6/04 · 박서연
    대상
    fd 누수
    조건
    파이프 100회 반복 실행 후 열린 fd 수 확인
    결과
    실행 전후 fd 수 동일
    남은 불확실성
    리다이렉션과 파이프를 섞은 경우는 10회만 확인

기여

각자 선언한 역할과 근거입니다. ‘팀원 확인’은 해당 팀원이 그 주장을 인정했다는 뜻이며 교수 인증이나 능력 검증이 아닙니다. 활동량을 점수나 비율로 환산하지 않습니다.

팀 결과

파이프·리다이렉션·백그라운드 실행을 지원하는 셸과 테스트 42개, 보고서 v2.
