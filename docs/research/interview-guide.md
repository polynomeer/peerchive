# 인터뷰 가이드

[검증 키트](README.md) · 관련: [실행 계획 §2.1](../planning/DELIVERY_PLAN.md#21-인터뷰)

공통 원칙
- 의견("이런 서비스 쓰실 건가요?")보다 **최근의 실제 경험**을 묻습니다. 미래 사용 의향은 근거로 쓰지 않습니다.
- 참여자가 자기 자료(단톡방, 노션, 드라이브)를 보면서 이야기하게 하되, 파일을 넘겨받지 않습니다.
- 서비스 아이디어는 인터뷰 마지막에만 짧게 보여 줍니다. 먼저 보여 주면 답이 아이디어 쪽으로 끌려갑니다.
- 진행자 1명 + 가능하면 기록자 1명. 노트는 참여자 코드로 작성합니다.

## A. 재학생 인터뷰 (45분, 8~12명, 코드 S01~)

**모집 조건:** 최근 1년 안에 조별과제 또는 팀 프로젝트를 한 학생. 학년·전공은 섞되 첫 대상 과목 수강자 우선.

| 시간 | 블록 | 질문 | 확인할 가설 |
|---|---|---|---|
| 0~5 | 시작 | 동의 확인, 녹음 여부, 진행 방식 안내 | – |
| 5~15 | 최근 팀 과제 재구성 | 1. 가장 최근 팀 과제 하나를 골라 주세요. 언제, 몇 명, 어떤 결과물이었나요? <br>2. 처음 과제를 받았을 때 무엇부터 했나요? 그때 어떤 정보가 있었으면 좋았을까요? <br>3. 팀은 어떤 도구로 소통했나요? (단톡방/디스코드/노션 등 실제 화면을 보며) | 첫 대상, 메신저 채널 |
| 15~25 | 기여와 갈등 | 4. 역할은 어떻게 나눴나요? 계획대로 됐나요? <br>5. 누가 무엇을 했는지 나중에 설명해야 했던 적이 있나요? (동료평가, 발표, 교수 면담) 그때 무엇을 근거로 썼나요? <br>6. 무임승차나 기여도 때문에 불편했던 경험이 있다면 구체적으로 말해 주세요. 그때 무엇이 있었으면 해결됐을까요? | 기여 장부 = 학기 중 핵심 가치 |
| 25~33 | 족보와 참고 자료 | 7. 과제를 하면서 선배 자료(족보)나 지난 학기 자료를 받아 본 적이 있나요? 어떻게 받았나요? <br>8. 그중 실제로 가장 도움이 된 건 무엇이었나요? (정답/소요시간/막히는 곳/조언/결과물 수준 중 직접 말하게 한 뒤 확인) <br>9. 받지 못해서 불리하다고 느낀 적이 있나요? | 족보 해부: 정답 외 가치 |
| 33~40 | 기록과 포트폴리오 | 10. 진행 중의 판단이나 실패, 막혔던 것을 어딘가에 남겼나요? 어디에, 얼마나 자주? <br>11. 그 과제를 포트폴리오·자소서에 쓴 적이 있나요? 쓸 때 무엇을 다시 찾거나 다시 만들어야 했나요? 얼마나 걸렸나요? | 기록 부담, 포트폴리오 재작성 비용 |
| 40~45 | 공개 의향과 마무리 | 12. 그 과제의 과정을 후배에게 공개한다면 어디까지 괜찮나요? 무엇은 절대 안 되나요? 누구의 동의가 필요하다고 생각하나요? <br>13. (목업이 준비된 경우) 과목 페이지를 30초 보고, 가장 먼저 눈이 간 것과 쓸모없어 보이는 것을 말해 주세요. | 공개 수준·엠바고 수용성 |

**탐침 질문(필요 시):** "그때 구체적으로 어떤 메시지였나요?" / "그걸 하는 데 시간이 얼마나 걸렸나요?" / "그 일이 없었다면 무엇이 달라졌을까요?"

**종료 후 5분 안에 기록할 것**
- 팀 채널: 디스코드 / 카카오톡 / 기타
- 기여 갈등 경험: 있음/없음, 심각도 1~5
- 족보에서 가장 유용했던 요소(본인 표현 그대로)
- 진행 중 기록 습관: 없음 / 가끔 / 정기
- 포트폴리오 재작성 시간(본인 추정)
- 공개 허용 범위: 비공개 / 요약 / 전체
- 인상적인 인용 1~2개(실명·식별정보 제거)

## B. 채용 검토자 인터뷰 + E4 (40분, 4~6명, 코드 R01~)

**모집 조건:** 최근 2년 안에 신입 서류·포트폴리오 검토 또는 면접 경험이 있는 개발자·PM·디자이너.

| 시간 | 블록 | 내용 |
|---|---|---|
| 0~5 | 시작 | 동의 확인. “서비스 평가가 아니라 신입 지원자를 보는 방식에 대한 이야기”임을 안내 |
| 5~15 | 현재 방식 | 1. 신입 지원서의 프로젝트를 볼 때 무엇을 가장 먼저 보나요? 한 건에 몇 분을 쓰나요? <br>2. 프로젝트가 다 비슷해 보인다고 느낀 적이 있나요? 무엇으로 구분하나요? <br>3. GitHub 링크를 실제로 열어 보나요? 열면 무엇을 보나요? <br>4. 최근 AI로 만든 결과물이 늘면서 판단 방식이 바뀌었나요? |
| 15~35 | **E4 비교** | 같은 가상 학생의 자료를 두 형태로 순서를 바꿔 제시(참여자마다 순서 교차). **형태 1:** GitHub 저장소 링크 + 3줄 소개. **형태 2:** [공개 프로필 목업](mockups/profile.html)과 [공개 사례 목업](mockups/case.html). 각 형태를 **90초** 본 뒤: (a) 이 학생의 주요 역할은? (b) 그 근거는? (c) 면접에서 물어볼 질문 2개 (d) 판단 확신도 1~5 |
| 35~40 | 마무리 | 5. 형태 2에서 믿기 어렵거나 과장처럼 보인 부분은? <br>6. “팀원 확인” 표시는 판단에 영향을 줬나요? <br>7. 이런 자료가 있다면 채용 과정 어디에서 쓰겠나요? (사용 의향은 근거로 쓰지 않고 맥락으로만 기록) |

**E4 채점 기준(사전 고정):** (a)·(b)가 가상 학생 설정과 일치하면 “정확”. (c) 질문이 특정 결정·막힘·검증을 가리키면 “구체적”, 기술 스택 일반 질문이면 “일반적”.

## C. 교수·조교·멘토 인터뷰 + E5 (30분, 2~3명, 코드 F01~)

| 시간 | 블록 | 질문 |
|---|---|---|
| 0~5 | 시작 | 동의 확인. 특정 학교 규정 해석을 요청하는 자리가 아님을 안내 |
| 5~15 | 현재 운영 | 1. 팀 과제 진행 상황을 어떻게 파악하나요? <br>2. 무임승차 문제를 어떻게 다루나요? 동료평가를 하나요? 근거는 무엇인가요? <br>3. 생성형 AI 이후 과제 평가 방식이 바뀌었나요? 과정을 보려고 하나요? |
| 15~25 | 공개와 엠바고(E5) | 4. 지난 학기 학생 과제의 *과정*(막힌 지점, 결정 이유, 중간 산출물)이 공개된다면 우려되는 점은? <br>5. 다음 규칙이면 어떤가요: 학기 종료 전 공개 불가, 과제 원문·정답 코드 비공개 권장, 요약 공개 선택 가능, 팀 전원 동의 필요. (허용 가능 / 조건부 / 불가, 조건은?) <br>6. 같은 과제를 매 학기 내나요? 그렇다면 공개 범위는 어떻게 달라져야 하나요? |
| 25~30 | 기여 리포트 | 7. 팀원별 기여 요약(로그·확인 상태, 점수 없음)을 동료평가 참고자료로 받는다면 쓸모가 있나요? 어떤 형식이어야 하나요? |
