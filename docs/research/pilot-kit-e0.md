# E0 수동 운영 키트: 노션 + 디스코드로 4주 빌드 로그

[검증 키트](README.md) · 관련: [제품 기획 §6·§7](../PROOFU_EVOLUTION_PLAN.md#6-과정-기록-칸반을-대신하는-빌드-로그--마일스톤), [측정](measurement.md)

**목적:** 앱을 만들기 전에, 빌드 로그·마일스톤·주간 체크인·기여 요약이 실제 팀 과제에서 4주간 유지되는지와 어디서 멈추는지 확인합니다.

**대상:** 진행 중인 팀 과제 2~3팀(팀당 2~5명). 절반은 **태그형 빌드 로그**, 절반은 **자유 기록**(태그·구조화 필드 없이 한 줄 메모)으로 시작합니다.

---

## 1. 노션 템플릿

팀마다 페이지 하나를 복제해 줍니다. 페이지 구성:

```text
📁 [과제명] — Peerchive 실험
  ├─ 개요 (과목·학기·과제 한 줄 요약·목표·마감·팀원과 역할)
  ├─ 🗂 빌드 로그 (데이터베이스)
  ├─ 🎯 마일스톤 (데이터베이스)
  ├─ ✅ 할 일 (데이터베이스, 보드 보기 선택)
  └─ 👥 역할 선언 (데이터베이스)
```

### 1.1 빌드 로그 데이터베이스 속성

| 속성 | 유형 | 값 / 설명 | 자유 기록 그룹 |
|---|---|---|---|
| 제목 | 제목 | 한 줄 요약 | 사용 |
| 태그 | 선택 | 🔨진행, 🧱막힘, 💡해결, ⚖️결정, 🗣️회의, ✅검증, 🔁회고 | **숨김** |
| 작성자 | 사람 | | 사용 |
| 본문 | 텍스트 | 한 일 / 알게 된 점 / 근거 (1~5줄) | 사용 |
| 첨부 | 파일·링크 | 사진·PDF·저장소 링크 | 사용 |
| 마일스톤 | 관계 → 마일스톤 | | 사용 |
| 해결한 막힘 | 관계 → 빌드 로그 | 💡해결일 때 연결할 🧱막힘 | 숨김 |
| 걸린 시간 | 선택 | 30분 미만 / ~2시간 / 반나절 / 하루 이상 | 숨김 |
| 오류 메시지 | 텍스트 | 🧱막힘일 때 선택 | 숨김 |
| 선택지·기준 | 텍스트 | ⚖️결정일 때: 선택지 → 판단 기준 → 선택 | 숨김 |
| 지나고 보니 | 텍스트 | ⚖️결정, 과제 종료 후 작성 | 숨김 |
| 정답 점검 | 체크박스 | “해결 부분이 과제 답 자체가 아님” | 숨김 |
| 입력 경로 | 선택 | 노션 / 디스코드 / 체크인 승격 / 운영자 대필 | 사용(운영자 기입) |
| 작성 시각 | 생성 일시 | 자동 | 사용 |

**뷰:** 타임라인(전체), 🧱막힘만, ⚖️결정만, 내 로그.

### 1.2 마일스톤 데이터베이스

| 속성 | 유형 | 설명 |
|---|---|---|
| 이름 | 제목 | 예: 기획 / 중간발표 / 구현 / 최종제출 |
| 순서 | 숫자 | |
| 예정일 | 날짜 | |

| 메모 | 텍스트 | 한 줄 |

### 1.3 역할 선언 데이터베이스

| 속성 | 유형 | 설명 |
|---|---|---|
| 선언 | 제목 | “화면 흐름 설계와 API 입력 검증을 맡았다” |

## 2. 디스코드 서버 구조

실험용 서버 하나에 팀별 카테고리를 둡니다. 이미 팀 디스코드가 있으면 그 서버에 채널 두 개만 추가합니다.

```text
📂 [팀명]
  # 작업         ← 평소 대화
  # 로그         ← 기록할 것만. "막힘: CORS 에러..." 처럼 태그 단어로 시작
  # 회의         ← 회의 메모
📂 운영
  # 공지          ← 체크인 알림, 주간 요약
  # 질문          ← 실험 관련 질문
```

**봇 없이 재현하는 규칙**
- `#로그`에 쓴 글, 또는 다른 채널 글에 📌 반응이 달린 글을 운영자가 매일 1회 노션 빌드 로그로 옮깁니다(입력 경로 = 디스코드).
- 남의 글에 📌을 단 경우, 작성자에게 “로그로 옮길까요?”를 묻고 동의할 때만 옮깁니다.
- 옮긴 글 수와 지연 시간을 기록해 봇의 가치를 추정합니다.

카카오톡을 쓰는 팀은 단톡방 그대로 두고 “로그:”로 시작하는 메시지만 팀원이 노션에 직접 붙여 넣게 합니다. 이 차이도 기록합니다.

## 3. 주간 체크인 폼 (구글 폼, 60초)

매주 일요일 20시에 `#공지`와 개인 메시지로 링크를 보냅니다. 월요일 12시 마감.

1. 참여자 코드 (드롭다운)
2. 이번 주 이 과제에 쓴 시간: 0 / ~2시간 / ~5시간 / ~10시간 / 10시간 이상
3. 체감 난이도: 1(쉬움) ~ 5(매우 어려움)
4. 이번 주 가장 중요한 진전 또는 막힘 한 줄 (선택)
5. 4번을 빌드 로그로 옮겨도 될까요? 예 / 아니오
6. 이번 주 기록을 못 했거나 덜 했다면 이유: 바빠서 / 귀찮아서 / 기록할 게 없어서 / 어디에 써야 할지 몰라서 / 기타 (복수)
7. (2주차·4주차만) 기록 1회에 보통 걸린 시간: 1분 / 3분 / 5분 / 10분 이상

## 4. 운영자 주간 루틴

| 요일 | 할 일 | 시간 |
|---|---|---|
| 매일 | 디스코드 `#로그`·📌 → 노션 옮기기, 지연 기록 | 10분 |
| 일 | 체크인 폼 발송 | 5분 |
| 월 | 체크인 집계, 승격 동의된 한 줄을 로그로 옮기기 | 15분 |
| 화 | **주간 기여 요약** 작성·팀에 공유(아래 양식) | 팀당 15분 |
| 금 | 측정 시트 갱신, 이탈 신호 확인(3일 이상 무기록 팀원) | 20분 |

### 4.1 주간 기여 요약 양식 (점수·순위 없음)

```text
[팀명] 주간 기여 요약 — N주차 (기간)
마일스톤: 중간발표 (예정 MM-DD) — 스냅샷 1개 등록

S03  🔨진행 2 · 🧱막힘 1(해결 1) · ⚖️결정 1
     역할 선언 “API 입력 검증” — 팀원 확인 1명
S04  🔨진행 1 · 🗣️회의 정리 1
     역할 선언 없음
미해결 막힘: “지도 API 쿼터 초과” (S04, 2일째)

※ 개수는 참고용이며 기여의 크기를 뜻하지 않습니다.
```

## 5. 종료 인터뷰 (4주차, 20분, 팀원별)

1. 기록을 남기게 된 가장 큰 이유와 멈추게 된 가장 큰 이유는?
2. 주간 기여 요약을 팀에서 어떻게 받아들였나요? 불편했던 점은?
3. 동료평가·발표에 이 기록을 쓸 수 있을 것 같나요? 실제로 썼나요?
4. 태그/필드 중 쓸모없었던 것, 없어서 아쉬웠던 것은? (자유 기록 그룹: 태그가 있었다면 썼을까요?)
5. 이 과제의 과정을 학기 후 후배에게 공개한다면 어디까지 괜찮나요?
